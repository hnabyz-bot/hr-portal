# regulations/

규정 검색 기능이 읽는 원문 파일이 들어가는 곳이다.

**이 폴더 안의 파일은 git에 올라가지 않는다** (`.gitignore` 처리됨, 이 `README.md`만 예외).
회사 규정 원문을 Public 저장소에 영구 공개하지 않기 위한 조치다 — 서버에 SSH로 직접 넣어야 한다.

## 넣어야 할 파일

`backend/rules_config.py`의 `RULES` 목록과 **파일명이 정확히 같아야** 한다 (공백·괄호·마침표 포함).
PDF를 권장한다 — 조항마다 "원본 PDF n쪽"으로 바로 갈 수 있다. 같은 이름의 `.docx`만 있으면 그것을 대신 읽는다(쪽 이동 없음).

## 서버에 넣는 방법

```bash
scp "1. 인사규정(2026.05).pdf" <계정>@<서버 주소>:~/workspace/github-hnabyz-bot/hr-portal/regulations/
```

(또는 SFTP 클라이언트로 같은 경로에 직접 업로드)

파일을 새로 넣거나 교체한 뒤에는 컨테이너를 재시작할 필요 없다 — `api` 컨테이너가 이 폴더를 읽기 전용으로 마운트하고 있고, 파일 수정시각을 기준으로 캐시를 갱신한다.

일부 파일만 먼저 넣어도 된다 — 없는 파일은 검색 결과에서 자동으로 빠지고, 서버 전체가 멈추지 않는다.

## 자주 묻는 질문의 쉬운 설명 — `faq.json`

"자주 묻는 질문" 탭에서 규정 원문 위에 먼저 보이는 풀어 쓴 설명이다. 회사 금액·기준이 들어 있어 원문과 마찬가지로 **이 폴더에만 두고 git에 올리지 않는다.**

```json
{
  "pay-5": "첫 문장.\n둘째 문장.\n\n# 소제목\n\n- 목록 한 줄\n- 목록 한 줄\n\n예) 흐리게 보이는 예시 문단"
}
```

- 열쇠: `public/index.html`의 `RULE_FAQ`에서 그 질문의 첫 조항 `규정 id-조 번호`.
- 글: 빈 줄로 문단을 나누고(문단 안의 줄바꿈은 화면에서도 줄이 바뀐다), 줄마다 `- `로 시작하면 목록, `# `로 시작하는 문단은 굵은 소제목, `예)`로 시작하는 문단은 예시.
- 파일을 바꾸면 바로 반영된다(재시작 불필요). 파일이 없거나 형식이 깨졌으면 설명 없이 규정 원문만 보인다.
