# 휴대폰 알림 · 앱 아이콘 숫자 — 설계 (2026-10-22)

휴대폰에 설치한 인사포털(홈 화면 앱)로 **처리할 일이 생기면 알림**을 보내고, **앱 아이콘에 숫자**를 붙인다.
시안: 인사담당자 PC `뉴디자인/휴대폰 알림 시안.html`·`.png`(저장소 밖) — 인사담당자 "너무 좋네"(2026-10-22).

## 1. 왜

- 인사담당자: "사이트를 모바일 앱 형태로 설치했을 때 알람이 생기면 아이콘 옆에 표시가 나오게 할 수 있나? 카카오톡도 채팅 오면 앱 우측 상단에 숫자로 나오잖아."
- 지금은 처리할 일(서명할 계약서, 승인할 KPI 등)을 포털을 열어야만 안다. 왼쪽 메뉴 숫자(`TODO`)와 홈 "오늘의 업무"(`homePortalTasks`)에만 보인다.
- 앱을 닫아 둬도 숫자가 바뀌려면 서버가 휴대폰으로 알림을 보내야 한다(웹 푸시). 인사담당자가 객관식에서 "푸시 알림 + 숫자"를 골랐다.

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

**목표**
- 처리할 일이 생기면 그 사람의 등록된 휴대폰으로 알림이 간다. 누르면 그 일을 처리하는 화면이 열린다.
- 앱 아이콘에 숫자가 붙는다(아이폰 = 처리할 일 개수, 갤럭시 = 안 읽은 알림 개수 — §4.3).
- 평일 아침 9시에 남은 일이 있는 사람에게 한 번 모아서 다시 알린다.

**하지 않을 것**
- PC로는 보내지 않는다. 등록된 휴대폰(한 사람에 한 대, `sessions.kind='phone'`)에만 보낸다.
- 처리할 일이 아닌 소식(KPI 확정됨, 생일·경조사 등)은 보내지 않는다.
- 직원이 종류별로 알림을 끄고 켜는 설정 화면은 만들지 않는다. 끄려면 휴대폰 설정에서 끈다.
- 오프라인 화면 저장(서비스 워커 캐시)은 하지 않는다. 서비스 워커는 알림만 다룬다.
- 하이웍스 메신저 알림은 쓰지 않는다(`docs/hiworks-api-setup.md`에 가능하다고 적혀 있음) — 인사포털 아이콘에 숫자를 붙일 수 없어서 요청과 맞지 않는다.

**실패로 보는 것 (기술적으로 돌아가도)**
- 알림 문구에 금액 · 다른 사람 이름 · 평가 등급이 들어가는 것. 잠금화면에 그대로 보인다.
- 근무시간 밖(평일 18시 뒤 · 주말)에 휴대폰이 울리는 것. 아침 9시 묶음 알림만 예외다(9시는 근무시간).
- 같은 시각에 같은 사람 휴대폰이 두 번 이상 울리는 것(아침 9시).
- 등록을 해제했거나 퇴사(비활성)한 사람, 다른 사람의 휴대폰으로 알림이 가는 것.
- HR이 급여명세서를 "공개"할 때 알림 보내기 때문에 화면이 느려지거나 공개가 실패하는 것.
- 비밀값(VAPID 개인키)이 저장소 · 커밋 · 로그에 들어가는 것.

## 3. 순서 — 연봉계약서 먼저 (인사담당자 결정, 2026-10-22)

- 연봉계약서 실제화(다른 창, 로컬 브랜치 `feature/contract-live`)가 `016_contracts.sql`, `public/index.html`, `backend/app.py`, `backend/payslip.py`, `check_schema.py`를 고친다. 이 작업과 같은 파일·같은 표 번호를 쓰므로 **계약서가 main에 들어간 뒤 시작한다.**
- 그래서 새 표 번호는 그때 main의 마지막 번호 + 1이다(지금 예상 017). 시작할 때 다시 확인한다.
- "서명할 연봉계약서" 알림은 계약서 쪽 "발송"(서명 요청) 지점에 붙인다. 계약서 설계: `docs/superpowers/specs/2026-10-22-salary-contract-live-design.md`(계약서 브랜치에 있음).

## 4. 사람이 보는 것

### 4.1 알림 켜기 칸 (휴대폰 홈, 인사 배너 바로 아래)

휴대폰 규칙상 직원이 직접 한 번 허용해야 알림이 온다. 허용 요청은 사용자가 누른 순간에만 띄울 수 있다(아이폰 규칙).

| 상태 | 칸 |
|---|---|
| 알림을 받을 수 있고 아직 안 켬 | 종 아이콘(붉은색) · **휴대폰 알림 켜기** · "처리할 일이 생기면 / 휴대폰으로 알려 드려요" · [켜기] |
| [켜기] → 휴대폰이 묻는 창에서 허용 | 칸이 사라지고 아래에 잠깐 "알림을 켰어요. 처리할 일이 생기면 알려 드릴게요" |
| 허용 안 함을 눌렀음(권한 거부) | 칸이 남고 문구가 "휴대폰 설정에서 인사포털 알림을 켜 주세요"로 바뀐다. [켜기] 대신 [방법 보기] — 갤럭시·아이폰 순서를 짧게 |
| 아이폰인데 홈 화면 앱이 아님(사파리에서 연 것) | "홈 화면에 추가하면 알림을 받을 수 있어요" · [추가 방법] → 기존 `installNotice()` |
| 이미 켬 | 칸 없음 |

- 보이는 조건: 실제 로그인(`AUTH.live`), 휴대폰 세션(`/api/me`의 `kind==='phone'`), 휴대폰 폭(`isPhone()`), 서버에 알림 키가 있음(§8.3).
- 브라우저가 알림을 아예 못 하면 칸을 보이지 않는다.
- 이미 켠 사람도 앱을 열 때마다 조용히 다시 등록한다(휴대폰이 받는 주소가 바뀔 수 있다). 묻는 창은 다시 띄우지 않는다.
- 모양은 시안 그대로(시안 파일은 저장소 밖이라 이 문장이 기준이다): 흰 카드, 왼쪽 원 안의 종(붉은 계열 `--bg-danger`/`--coral-text`), 오른쪽 파란 [켜기] 단추. 설명 줄은 두 줄로 끊는다(한 단어만 다음 줄로 넘어가지 않게).

### 4.2 알림 문구

휴대폰이 제목 위에 "인사포털"을 붙인다. 문구는 "~요"체. **금액 · 다른 사람 이름 · 등급은 넣지 않는다.** 달·연도는 넣어도 된다.

| 일 | 받는 사람 | 제목 / 내용 | 누르면 |
|---|---|---|---|
| 급여명세서 공개 | 공개된 달의 명세서가 있는 직원 | **10월 급여명세서가 올라왔어요** / 눌러서 확인해 주세요 | 급여·계약 > 급여명세서 |
| 원천징수영수증 공개 | 공개된 해의 영수증이 있는 직원 | **2025년 원천징수영수증이 올라왔어요** / 눌러서 확인해 주세요 | 급여·계약 > 원천징수영수증 |
| 연봉계약서 서명 요청 (처음 발송 · 파기 후 다시 발송 모두) | 계약 당사자 | **서명할 연봉계약서가 있어요** / 눌러서 내용을 확인하고 서명해 주세요 | 급여·계약 > 연봉계약서 |
| 연봉계약서 문의(직원이 [HR에 문의]) | 활성 HR 전원 | **답변할 연봉계약서 문의가 있어요** / 눌러서 확인해 주세요 | 급여·계약 > 연봉계약서(HR) |
| KPI 계획서 제출 · 변경 요청 · 일정 변경 요청 | 승인할 사람 | **팀원 KPI 승인 요청이 왔어요** / 눌러서 확인해 주세요 | 평가·성과 > KPI |
| KPI 계획서 돌려보냄(반려) | 작성한 사람 | **KPI 계획서가 돌아왔어요** / 사유를 확인하고 다시 작성해 주세요 | 평가·성과 > KPI |
| KPI 확인 메모 · 메모 수정 | 메모를 받은 사람 | **KPI 확인 메모가 왔어요** / 눌러서 확인해 주세요 | 평가·성과 > KPI |
| 확인 메모에 새 답글 | 상대편(작성자 ↔ 받은 사람) | **확인 메모에 새 답글이 달렸어요** | 받은 사람이면 KPI, 작성자면 KPI 현황 |
| 아침 9시 묶음 | 남은 일이 1건 이상인 사람 | **처리할 일이 N건 있어요** / 종류를 " · "로 이어 씀(예: "새 급여명세서 · 처리할 KPI 2건") | 홈 |

- KPI 지난달 한 줄(매월 1~7일)과 KPI 월간 확인은 무언가 "생기는" 일이 아니라 날짜·상태로 정해지는 일이라 **아침 9시 묶음에만** 들어간다.
- 같은 KPI 계획서를 두 번 이상 제출하는 경우처럼 같은 일이 짧은 사이에 반복되면, 알림이 반복돼도 괜찮다(드문 일). 막을 필요가 생기면 그때 더한다.
- 종류 이름은 화면의 `homePortalTasks` 제목과 같게 쓴다("새 급여명세서", "처리할 KPI", "반려된 KPI 다시 작성", "KPI 지난달 한 줄 쓰기", "확인 메모 확인", "KPI 월간 확인", "확인 메모에 새 답글", "연봉계약서 서명", 계약서 브랜치의 HR 문의 줄 제목).

### 4.3 앱 아이콘 숫자

| 휴대폰 | 숫자 | 근거 |
|---|---|---|
| 아이폰 (iOS 16.4 이상, 홈 화면 앱) | 처리할 일 개수 | Badging API(`setAppBadge`) — 알림 권한이 있어야 보인다 |
| 갤럭시 등 안드로이드(크롬) | 안 읽은 인사포털 알림 개수(또는 점 — 홈 화면 앱 설정에 따름) | 안드로이드 크롬은 Badging API가 없고, 알림이 있으면 런처가 숫자를 붙인다 |

- 알림을 보낼 때 그 사람의 처리할 일 개수(§7)를 함께 실어 보내고, 서비스 워커가 받으면 `setAppBadge(개수)`(0이면 `clearAppBadge`)를 부른다. 지원하지 않는 휴대폰에서는 부르지 않는다.
- 앱을 열어 둔 동안은 화면이 왼쪽 메뉴 숫자의 합(`homePortalTasks` 합계)으로 아이콘 숫자를 맞춘다(처리하면 바로 준다).
- 앱을 열면 떠 있는 인사포털 알림을 모두 닫는다(`registration.getNotifications()` → `close()`). 그래서 갤럭시 숫자는 앱을 열면 사라진다 — 카카오톡에서 채팅방을 열면 숫자가 지워지는 것과 같은 느낌. 앱 안 메뉴 숫자는 그대로 남는다.
- 인사담당자에게 알린 것: 갤럭시에서 알림을 밀어서 지우면 일이 남아 있어도 숫자가 사라진다.
- **삼성 인터넷으로 설치한 갤럭시**(설치 안내 `INSTALL_STEPS.galaxy`에 삼성 인터넷 순서도 있다): 알림·숫자가 인사포털 아이콘이 아니라 삼성 인터넷 앱에 붙을 수 있다. 만들 때 실제 갤럭시로 먼저 확인한다(내 판단). 인사포털 아이콘에 숫자가 붙지 않으면 — 알림 켜기 칸이 삼성 인터넷(`SamsungBrowser`)일 때 "크롬으로 설치하면 아이콘에 숫자가 보여요"를 덧붙이고, 설치 안내는 크롬을 먼저 적는다. 알림 자체는 삼성 인터넷에서도 받게 둔다.

### 4.4 알림을 누르면

- 앱이 열려 있으면 그 창을 앞으로 가져오고 화면을 옮긴다. 닫혀 있으면 새로 연다.
- 주소: `/?go=<메뉴>.<탭>` (예: `/?go=pay.p1`). 로그인 확인(`authBoot`)이 끝난 뒤 `goTo(메뉴, 탭)`으로 옮기고 주소에서 `go`를 지운다. 모르는 값이면 홈.
- 알림을 눌러 들어온 경우에도 "오늘 할 일" 창 규칙(`todayPopAuto`, 새로 들어올 때마다)은 그대로 둔다 — 단, 옮겨 간 화면 위에 창이 덮이지 않도록 `go`가 있으면 그 창은 띄우지 않는다(내 판단).

## 5. 보내는 때 (인사담당자 결정)

- **근무시간 = 평일(월~금) 9:00~18:00, 한국 시간.** 서버 컨테이너 시계가 UTC일 수 있으므로 UTC+9로 계산한다(한국은 서머타임이 없다). 공휴일은 빼지 않는다(내 판단 — 필요해지면 휴일 목록을 더한다).
- 근무시간에 일이 생기면 **바로** 보낸다.
- 근무시간 밖에 생긴 일은 **그때 보내지 않는다.** 다음 근무일 9시 묶음 알림에 저절로 들어간다(묶음은 그 시각의 남은 일 전체를 세므로 따로 쌓아 둘 표가 없다).
- **평일 9시 묶음**: 남은 일이 1건 이상인 사람에게 "처리할 일이 N건 있어요" 한 통. 밤사이 생긴 일과 전부터 남은 일을 합친다(같은 시각에 두 번 울리지 않게 — 내 판단).
- 묶음 알림은 같은 날 두 번 돌지 않게 한다(마지막으로 돈 날짜를 기록).

| 연봉계약서 문의 | 계약서 브랜치가 들어온 뒤 | 직원이 [HR에 문의]를 보내는 지점 | 활성 HR 전원(`user_roles.role='HR_ADMIN'`) |
| 평가 진행 · 이의 신청 | **없음**(화면의 시연 자료뿐, `evTodo`·`evPeople`) | 이번에는 보내지 않는다. 평가 실제화 때 같은 함수로 붙인다 | — |

- 인사담당자는 평가·이의 신청도 골랐다. 서버 기능이 없어서 이번에는 붙일 곳이 없다 — 설계 승인 때 알린다. 평가를 서버로 옮기는 일은 평가·성과 실제화 설계의 **3단계**이고, 시기는 "2026년 연말 평가는 포털 밖에서, 3단계는 2027년 12월 평가 시작 전까지"(인사담당자 결정 2026-10-20, `2026-10-20-kpi-progress-and-live-evaluation-design.md` 3장)다. 3단계를 만들 때 이 설계의 보내기 함수와 `pending()`에 평가·이의 신청을 더한다.
- 파일:줄 번호는 계약서가 들어오면 바뀐다. 함수 이름으로 찾는다.

## 7. 처리할 일 개수 (서버)

알림에 실을 아이콘 숫자와 9시 묶음 문구에 쓴다. 화면의 `homePortalTasks()` 합계(= 왼쪽 메뉴 숫자 합 `TODO`)와 **같은 기준**이어야 한다. 지금은 서버에 이 합계를 내는 함수가 없다 → `pending(conn, uid) -> list[(종류, 개수)]`를 새로 만든다.

| 화면 | 서버에서 셀 것 |
|---|---|
| p1 새 급여명세서 | OPEN인 달의 내 명세서 중 안 본 것(`payslip.py`의 내 목록 쿼리와 같은 조건) |
| p2 연봉계약서 서명 | 계약서 브랜치의 "서명 대기" 조건 |
| p2 연봉계약서 문의 (HR) | 계약서 브랜치의 "답하지 않은 문의" 조건 — 계약서 설계 4.5 · 4.10의 HR 메뉴 숫자와 같게 |
| p3 새 원천징수영수증 | OPEN인 해의 내 영수증 중 안 본 것 |
| e1 처리할 KPI | 내 처리함 항목 수(`inbox`) |
| e1 반려된 KPI 다시 작성 | 내 계획서 `note_kind='RETURNED'` |
| e1 KPI 지난달 한 줄 | `progress_json(me)["todo"]["prev"]` |
| e1 확인 메모 확인 | `_review`의 `memos` |
| e4 KPI 월간 확인 · 새 답글 | `_review`의 `check`·`replies` — 팀장·본부장·대표이사·HR만(화면 `kvCanUse`와 같게) |
| e2 평가 · e3 이의 신청 | 0 (서버 기능 없음) — **화면도 실제 로그인이면 0으로 바꾼다**(아래) |

- **대표이사 위임 중 (인사담당자 결정 2026-10-22)**: 처리함(`inbox`)의 `proxy()`는 맡긴 일을 대표이사 처리함에도 남긴다. 알림 · 9시 묶음 · 아이콘 숫자에서는 **맡긴 일을 대표이사 몫에서 뺀다**(HR 몫에만 센다). 대표이사가 앱을 열었을 때 화면이 맞추는 아이콘 숫자도 같은 기준으로 뺀다. 왼쪽 메뉴 숫자는 지금 그대로 둔다(대표이사는 처리함에서 볼 수 있다).
- **화면의 평가 숫자**: 실제 로그인에서는 e2·e3를 0으로 센다 — §7.1.
- 주의: `inbox()`·`_review`·`_sees`는 요청의 `g.actor`를 읽는다. 다른 사람 것을 셀 때는 `actor_of(conn, uid)`로 그 사람을 세워 같은 함수를 부르거나, 함수가 actor를 인자로 받게 고친다(만드는 사람이 고른다). **화면과 숫자가 다르면 안 된다** — 검사(§11)로 맞춰 본다.

### 7.1 실제 로그인의 평가 화면 · KPI 작성 기간 안내 (인사담당자 결정 2026-10-22 — 이 작업에 함께)

**왜**: 지금 `TODO.e2`(`evTodo`)·`TODO.e3`(`evPeople`)와 평가 화면(`evContent`·`evResultContent`)은 실제 로그인에서도 시연 자료를 쓴다(화면 위에 "시연용 가상 자료" 한 줄만). `kpiPeriod.evalFrom`이 `KPI_YEAR-12-01`이라 **2026-12-01부터 실제 로그인 메뉴 · 홈 "오늘의 업무" · "마감 임박"에 시연 평가 숫자가 붙는다**(HR은 `evAttDone`이 비어 있어 늘 +1). 2026년 평가는 포털 밖에서 한다(2026-10-20 결정). 인사담당자: "가짜 평가 진행은 이렇게 막았으면 — 평가가 진행되고 등급까지 확정되면 KPI 작성 화면은 수정 불가한 막힌 상태로 유지되고, 1월 1일이 되면 'KPI 작성 기간이 열립니다' 같은 안내."

| 시기 | 실제 로그인 화면 |
|---|---|
| 평가 시작일(HR이 넣는 `evalStart`)부터 12월 31일 | **KPI 작성 화면은 잠긴 채**(지금 규칙 — 평가 시작일부터 작성 기간이 닫힌다). 닫힘 띠 문구를 "평가가 시작되어 올해 KPI는 고칠 수 없어요"로 바꾼다(지금은 "작성 기간이 아니에요" — 내 판단). 진행 기록 · 일정 변경 요청 규칙은 그대로 |
| 12월 내내 (평가는 포털 밖) | **평가·성과 > 평가 진행, 평가 결과 두 탭은 시연 자료를 모두 숨기고 안내만**: "2026년 평가는 포털 밖에서 진행합니다." 메뉴 · 홈 "오늘의 업무" · "마감 임박"의 평가 숫자 · 날짜는 0 · 없음 |
| 1월 1일부터 (KPI 화면이 새해로 넘어감 — 서버가 한국 날짜로 올해를 정한다) | HR이 새해 작성 기간을 넣어 두었고 아직 시작 전이면 KPI 화면 맨 위 띠: **"KPI 작성 기간이 열립니다 · 1월 5일 ~ 1월 16일"**. 기간 중에는 지금 띠("작성 기간 1/5 ~ 1/16 · N일 남음"), 기간을 아직 안 넣었으면 지금 문구("HR이 작성 기간을 열면 쓸 수 있어요"). 쓰는 것은 HR이 정한 기간 안에서만 — 1월 1일에 저절로 열리지 않는다 |

- 포털은 2026년 등급이 언제 확정됐는지 모른다(평가가 포털 밖). 그래서 잠그는 시점은 **HR이 넣는 평가 시작일**이다.
- HR은 12월에 새해 작성 기간을 미리 넣을 수 있다(KPI 관리 화면의 해 고르기 — `/api/kpi/admin?year=`). 안내는 KPI 화면이 새해로 넘어가는 1월 1일부터 보인다.
- 홈 KPI 카드의 "작성 기간이 아니에요"도 같은 기준으로 "KPI 작성 기간이 열립니다 · 날짜"를 보인다(내 판단).
- 평가 결과 탭 안의 HR "보고서 엑셀 내려받기"(PR #173)와 이의 신청도 실제 로그인에서는 함께 숨는다 — 지금은 시연 결과로 만들어지기 때문이다. 시연 모드(서버 없음)와 임원 발표용 시연 사이트는 지금 그대로 시연 자료를 보인다(내 판단 — 설계 승인 때 확인).
- 평가 3단계에서 이 안내를 실제 평가 화면으로 바꾼다.

## 8. 서버

### 8.1 저장

새 표 `push_subscriptions` (번호는 §3):
- `token_hash` (기본키, 휴대폰 세션 `sessions.token_hash`) · `user_id` · `endpoint` · `p256dh` · `auth` · `created_at`.
- 세션 하나에 구독 하나. 같은 세션이 다시 등록하면 덮어쓴다.
- `check_schema.py`의 기대 표 목록·번호 검사에 더한다.

보낼 대상 = 구독 중에서 세션이 살아 있는 것만: `sessions.kind='phone'`, `revoked_at IS NULL`, 마지막 사용 30일 안(`_phone_of`와 같은 조건), 그리고 활성 직원. 그래서 로그아웃·등록 해제·퇴사 처리 경로마다 지우지 않아도 다른 사람이나 해제된 휴대폰으로 가지 않는다. 푸시 서버가 404·410(없어진 구독)을 돌려주면 그 줄을 지운다. 로그아웃(`logout`)과 휴대폰 해제(`phone_revoke`, `members_phone_revoke`)에서는 바로 지운다(정리용).

### 8.2 주소(API)

| 주소 | 하는 일 |
|---|---|
| `GET /api/push/key` | 공개키(VAPID public key). 서버에 키가 없으면 404 → 화면은 알림 켜기 칸을 숨긴다 |
| `POST /api/push/subscribe` | 이 휴대폰 세션의 구독 저장. **휴대폰 세션(`g.session_kind=='phone'`)만**, 아니면 403 |
| `POST /api/push/unsubscribe` | 이 세션의 구독 지우기 |

로그인 필요(기존 규칙대로 `/api/` 전부). 같은 출처 검사 등 기존 POST 규칙을 따른다.

### 8.3 보내기

- 라이브러리: `pywebpush`를 더한다(내 판단 — 웹 푸시 암호화·VAPID 서명을 직접 짜지 않는다). `requirements.txt`에 버전 고정.
- 비밀값: `.env`의 `HR_PUSH_PUBLIC` · `HR_PUSH_PRIVATE`(base64url 한 줄 — PEM은 `check-secrets.sh`에 걸리므로 쓰지 않는다), `docker-compose.yml`로 넘긴다. `.env.example`에 만드는 법을 적는다. VAPID subject는 사이트 주소(`https://hr.abyz-lab.work`) — 개인 메일 주소를 넣지 않는다.
- 키가 없으면 보내기는 조용히 건너뛴다. 다른 기능(공개·제출 등)은 그대로 된다.
- **요청을 붙잡지 않는다.** 일을 처리한 요청이 commit한 뒤 보내기를 뒤로 돌린다(백그라운드 스레드 등 — 만드는 사람이 고른다). 급여명세서 공개처럼 수십~백여 명에게 가도 HR 화면은 바로 끝나야 한다. gunicorn 작업자 2개 · 시간 제한 30초.
- 보내기 실패는 공개·제출을 되돌리지 않는다. 로그에는 개수와 상태 코드만 남긴다(이름·주소·문구 없음).
- 근무시간 판단(§5)은 보내는 함수 한 곳에서 한다.

### 8.4 아침 9시

- 명령: `docker compose exec -T api python -m push morning` (기존 `hr_eval.roster_sync`와 같은 방식). 평일이 아니면 아무것도 안 한다. 같은 날 이미 돌았으면 건너뛴다.
- 서버의 systemd 타이머로 **평일 9:00(한국 시간)** 에 돌린다. 타이머 파일 내용은 `DEPLOY.md`에 적는다. 서버에 올리는 것은 인사담당자가 ssh로 한다(§9).
- 앱 안에 예약 작업을 두지 않는다 — gunicorn 작업자가 2개라 두 번 돈다.

### 8.5 서비스 워커

- `public/sw.js`(사이트 전체 범위). `push` → `showNotification(제목, { body, icon: 앱 아이콘, data: { url } })` + 아이콘 숫자(§4.3). `notificationclick` → 열린 창을 찾아 앞으로·옮기기, 없으면 새 창.
- 9시 묶음 알림은 `tag:'morning'`으로 전날 묶음을 대신한다. 나머지는 tag 없이 하나씩 쌓는다.
- 등록은 `index.html`에서 휴대폰 실제 로그인일 때만 한다. 캐시는 하지 않는다.
- `public/xray/sw.js`(범위 `/xray/`)와는 범위가 달라 부딪히지 않는다.
- `nginx.conf`에 `location = /sw.js`를 더해 캐시를 막는다(`Cache-Control: no-cache`) — 앞단 Cloudflare가 `.js`를 오래 들고 있지 않게.

## 13. 남는 위험 (인사담당자에게 알림)

- 갤럭시 숫자는 "안 읽은 알림 개수"라 처리할 일 개수와 다를 수 있다.
- 아이폰은 홈 화면에 설치하고 알림을 허용해야만 된다. 사파리에서 연 포털에서는 안 된다.
- 알림은 구글·애플의 푸시 서버를 거쳐 간다. 내용은 암호화되어 그들이 읽을 수 없지만, "언제 인사포털 알림이 갔는지"는 그들이 안다.
- 9시 타이머가 서버에 없으면 아침 알림이 오지 않는다(근무시간 알림은 온다).
- 휴대폰이 절전·방해금지 상태면 휴대폰이 알림을 늦추거나 숨길 수 있다.
