## 3. 규칙

| 항목 | 규칙 |
|---|---|
| KPI 개수 | 실행목표(가중치가 붙는 행) **최소 3개, 상한 없음**. 목표·행 추가/삭제 자유 |
| 가중치 | 각 행 0 초과, **전체 합 정확히 100**. 아니면 제출 버튼 비활성 |
| 작성·수정 기간 | HR이 시작일~종료일 지정. **기간 밖에서는 입력·버튼 전부 비활성(조회만)** |
| 최초 작성 | 작성중 → 제출 → 1차 팀장 → 2차 본부장 → 확정(잠금) |
| 수정 | 확정 후 수정 기간에만 "수정 요청"(사유 필수) → 1차 팀장 → 2차 본부장 → 반영. **승인 전까지 기존 KPI 유효**, 반려 시 기존 유지. 미결 요청은 1인 1건 |
| 결재선 예외 | 팀장 본인: 본부장 1단계. 본부장 본인: **대표이사** 1단계(2026-10-13 — 그 전에는 HR). 팀 없는 본부 직속: 본부장 1단계. 본부장 없는 직속부서: 팀원은 팀장 1단계, 팀장은 **대표이사** 1단계(2026-10-13 — 그 전에는 HR 확인) |
| 달성 기준 (2026-10-13) | 실행목표마다 S~D 달성 기준을 **모두 적어야** 제출된다. 연말 평가의 기준이 된다 |
| 반려된 KPI (2026-10-13) | 작성 기간이 끝나도 고쳐서 다시 낼 수 있다 |
| 평가가 시작된 뒤 (2026-10-13) | 그해 평가 시작일부터는 KPI 수정을 요청하거나 반영할 수 없다 — 평가 항목이 바뀌면 이미 적은 실적·점수와 어긋난다 |
| 증빙 업로드 | **평가 기간에만**, 확정된 KPI의 행별로. 승인 불필요. PDF·이미지·엑셀·워드·한글, 파일당 10MB |
| 담당자명 | 본인 이름 자동 입력(수정 가능) |
| 진행률 (2026-09-22 추가) | 확정된 KPI의 실행목표별로 **본인이 0~100%를 직접 입력**. 목표 변경이 아니므로 기간·승인 제한 없음. 홈 화면 "나의 KPI 현황" 카드의 종합 달성률 = Σ(가중치 × 진행률)/100. 본인 신고값이며 평가 점수와 별개 |

### 홈 화면 (2026-09-22 추가)

> **2026-10-11 홈 개편으로 바뀜**: "나의 KPI 현황" 카드는 맨 아래 "나의 KPI 진행률"(상태 배지·종합 달성률·실행목표별 막대·상세 링크, KPI가 있는 직원에게만)로 줄였고, 승인 대기 건수는 홈 "오늘의 업무"로, 기간 D-day는 홈 "일정" 달력으로 옮겼다. 증빙 건수는 홈에서 뺐다. 자세한 것은 저장소 `CLAUDE.md`의 "홈 화면 개편".

결재 대기함 카드를 **나의 KPI 현황**(상태 배지, 종합 달성률, 실행목표별 진행 막대, 증빙 건수, 승인자에게는 팀원 승인 대기 건수, 상세 링크)으로 교체하고 **일정** 카드(수정 기간 D-day, 평가 기간)를 추가한다. 기간은 HR이 KPI 화면에서 설정한 값을 그대로 쓴다.

## 7. KPI 현황 — 직책별 화면 (2026-10-12 추가, 인사담당자 확정)

### 한 문장 정의

팀장·본부장·대표이사·HR이 자기 범위 사람들의 KPI 내용과 진행률을 보고, 진행이 부진한 사람을 알람으로 가려내 챙기는 화면. 평가·성과의 새 탭 "KPI 현황"이며 직원·현장직에게는 보이지 않는다.

### 누가 무엇을 보나

| 직책 | 본인 KPI | KPI 현황에서 보는 것 | 눌러야 나오는 것 |
|---|---|---|---|
| 직원 | 작성 | 탭 없음 | — |
| 팀장 | 작성 (**팀장 KPI = 부서 KPI**) | 자기 팀원 | 부서원 이름 → KPI 항목·진행률 |
| 본부장 | 작성 (**본부장 KPI = 본부 KPI**) | 자기 본부의 팀장·팀원 | 부서 → 팀장 KPI와 팀원 명단 → 팀원 이름 → 개인 KPI |
| 대표이사 | **없음** — 올해 경영계획 목표만 | 본부장·팀장까지 (팀원은 인원·평균·부진 수만) | 본부 → 본부장 KPI와 소속 부서 → 부서 → 팀장 KPI |
| HR 담당자·HR 팀장 | 작성 | 전 직원 — 본부별·부서별·개인별 | 본부 → 부서 → 이름 |

명단은 처음부터 KPI를 펼쳐 놓지 않는다. 왼쪽 명단에서 이름·부서를 누르면 오른쪽에 그 KPI가 나온다.

### 규칙

| 항목 | 규칙 |
|---|---|
| 종합 진행률 | Σ(가중치 × 진행률)/100. 확정된 KPI만 센다. 확정 전(작성중·승인 대기)은 상태만 보이고 알람이 없다. 현장직은 "KPI 대상 아님" |
| 기대 진행률 | 오늘까지 지나간 기간 비율 = 1월 1일부터 오늘까지 날수 ÷ 그해 날수 (10월 12일 = 78%). 막대 위 세로선으로 표시 |
| **부진 알람** (빨간 종) | 진행률이 기대 진행률보다 **20%p 이상** 낮을 때. 숫자는 HR이 목표설정 탭의 "KPI 현황 알람 기준"에서 바꾼다. **알람을 끈 항목은 빼고** 나머지 항목의 가중 평균으로 따진다(아래 "알람 끄기"). 화면에 보이는 종합 진행률 숫자는 끈 항목을 포함한 그대로다 |
| **갱신 필요** (시계) | 진행률(또는 늦어지는 이유)을 **30일 넘게** 고치지 않았을 때. 숫자는 HR이 바꾼다. 처음 확정된 날부터 센다 |
| 알람을 보는 사람 | 팀장·본부장·대표이사·HR, 그리고 **본인** (2026-10-13 변경 — 처음에는 본인 화면에 띄우지 않았다). 본인에게는 목표설정 탭의 KPI 표 위에 붉은 한 줄, 홈 "나의 KPI 진행률" 제목 옆에 종으로 보인다. 메뉴 숫자로는 세지 않는다 |
| **알람 끄기** (2026-10-13 추가) | 연말이나 특정 달에 끝나는 일처럼 지금 진행률이 낮은 것이 당연한 항목이 있다. **본인이 KPI 항목마다** 끈다(늦어지기 전에 미리 꺼도 된다). 이유는 눌러서 고른다: 연말에 끝나는 일 / 특정 달에 끝나는 일 / 외부 일정을 기다리는 중 / 직접 적기(50자). **고른 달의 말일까지** 꺼 두고 다음 달 1일부터 저절로 다시 켜진다(연말에 끝나는 일은 올해 말까지). 그 KPI를 볼 수 있는 사람에게 항목 아래 "본인이 알람 끔 · 이유"가 보이고, **본인과 바로 위 관리자가 다시 켤 수 있다.** 모든 항목을 끄면 알람이 없다. 목표 변경이 아니므로 기간·승인 제한이 없다 |
| 윗단계 표시 | 부서 줄에는 "팀원 부진 n명", 본부 줄에는 "소속 부진 n명". 부서 줄의 종은 팀장 KPI(부서 KPI)가 부진할 때 |
| 늦어지는 이유 | 본인이 확정된 KPI의 실행목표마다 한 줄(100자) 적는다. **선택 사항**, 언제든 고친다(목표 변경이 아니므로 기간·승인 제한 없음). 그 KPI를 볼 수 있는 사람에게 항목 아래에 보인다 |
| 확인 메모 | 팀장과 팀원(본부장과 팀장)이 **서로 확인했다는 기록**이다 (2026-10-13 변경 — 처음에는 본인에게 보이지 않는 관리자용 기록이었다). **바로 위 관리자만 쓴다**: 팀원은 팀장이, 팀장은 본부장이. **본인이 본다** — 목표설정 탭의 내 KPI 아래 "확인 메모" 칸. 그 사람의 KPI를 볼 수 있는 윗사람과 HR도 함께 보지만 읽기만 한다. 본부장과 본부장 없는 직속부서 팀장에게는 쓸 사람이 없어 메모 칸이 없다. 메모가 있으면 이름 옆에 말풍선 |
| 확인 · 답글 (2026-10-13 추가) | 본인은 메모마다 **"확인했습니다"** 를 누른다(날짜가 남고 취소할 수 없다). **답글은 본인과 쓴 사람만** 단다(200자). 본인이 답글을 달면 확인한 것으로 보고, 쓴 사람이 답글을 달면 본인이 다시 확인한다. 쓴 사람은 **쓴 당일에만** 메모를 고치거나 지울 수 있고, 고치면 확인 표시가 풀린다. 답글은 고칠 수 없고 단 사람이 당일에만 지운다 |
| 메모 알림 (2026-10-13 추가) | 본인: 확인하지 않은 메모 수를 평가·성과 메뉴 숫자와 홈의 처리할 일에 넣는다. 쓴 사람: 아직 못 본 본인 답글이 있으면 KPI 현황 탭 숫자와 명단의 붉은 말풍선으로 알리고, 그 사람을 열어 보면 본 것으로 한다. 길어지지 않게 최근 메모와 확인·답글이 필요한 메모만 펼치고 나머지는 "지난 메모 N건"으로 접는다 |
| 경영계획 목표 | HR이 등록·수정(목표·내용 여러 줄). 대표이사의 목표설정 탭에 KPI 대신 보이고, **본부장의 목표설정 탭에는 내 KPI 위에 참고로** 보인다(2026-10-13 추가). 대표이사·본부장·HR만 본다 |
| 대표이사 | KPI 현황은 조회만 한다. **본부장·직속부서 팀장의 KPI는 승인한다**(2026-10-13 — 그 전에는 HR 확인이었다. 3장). 연말 평가에서 하는 일은 8장 |
| HR 엑셀 | 전 직원 한 줄씩: 본부·부서·이름·직급·구분·상태·종합 진행률·기대 진행률·차이·부진·마지막 갱신·갱신 필요·확인 메모 건수·확인 안 한 메모 건수·늦어지는 이유·알람 끈 항목 수·알람 끈 이유. 지금은 엑셀에서 열리는 CSV 파일 |

### 결재선 (3장에 더함)

- 본부장이 없는 대표이사 직속부서: 팀원은 팀장 1단계, 팀장은 **대표이사 1단계**(2026-10-13).
- ~~"HR 확인"은 HR 담당자·HR 팀장 누구나 할 수 있다~~ → HR 확인 단계는 없어졌다(2026-10-13). 본부장과 직속부서 팀장의 KPI는 대표이사가 승인하고, 대표이사가 "HR에 맡기기"를 켜면 HR이 대신 승인한다(본인 것은 제외 — 8장).
- HR 팀장 = 지원팀 팀장. HR 팀장은 모든 메뉴에서 HR 담당자와 같은 HR 권한을 쓴다.

### 기본값으로 둔 것 — 인사담당자 확인 필요

1. ~~확인 메모는 본인에게 보이지 않는다~~ → **본인에게 보인다** (인사담당자 확정 2026-10-13). 열람 요청 처리 문제는 없어졌다.
2. ~~확인 메모는 고치거나 지울 수 없다~~ → **쓴 당일에만 고치거나 지운다** (인사담당자 확정 2026-10-13).
3. ~~경영계획 목표는 대표이사와 HR만 본다~~ → **대표이사·본부장·HR이 본다** (인사담당자 확정 2026-10-13, #116 ⑦). 본부장은 목표설정 탭의 내 KPI 위에서 본다. 팀장·직원에게는 보이지 않는다.
4. ~~HR 담당자·HR 팀장의 평가는 아직 정하지 않았다~~ → HR 담당자는 HR 팀장이, HR 팀장(직속부서 팀장)은 대표이사가 평가한다 (인사담당자 확정 2026-10-13, 8장).
5. 대표이사는 급여·계약 메뉴에 자료가 없다("등록된 명세서·계약서가 없습니다").
6. 알람을 끄면 **고른 달의 말일까지** 꺼 둔다. 인사담당자는 "고른 달이 되면 다시 켜짐"을 골랐으나, 그 달 안에는 아직 하는 중이라 다음 달 1일부터 켜지게 제안해 그대로 두었다.
7. 확인은 취소할 수 없다. 답글은 고칠 수 없다(당일 삭제만). 본부장(팀원의 메모)·HR·대표이사는 읽기만 한다.
8. 본인이 알람을 끌 때 팀장 승인은 받지 않는다 — 팀장이 이유를 보고 다시 켤 수 있는 것으로 갈음한다(인사담당자 확정 2026-10-13).

### 이번 범위 / 나중

**이번**: `public/index.html`의 `kv*` 함수와 `.kv-*` 모양. 시연 역할에 대표이사·HR 팀장을 더했다. 사람·KPI·메모는 브라우저 메모리의 가상 값이고, 시연 역할이 있는 다섯 명(직원·팀장·본부장·HR 담당자·HR 팀장)은 목표설정 탭의 확정 KPI·진행률을 그대로 읽는다.

**나중(로그인·DB 이후)**: 조직도·평가·KPI 현황에 따로 있는 시연용 명단을 하나로 합친다. 열람·메모 권한을 서버에서 검사한다(`kvCanView`·`kvCanMemo`·`kvMemoRole`과 같은 규칙). 진행률 갱신일·늦어지는 이유·확인 메모(확인 날짜·답글 포함)·알람 끄기를 저장한다 — 그래야 팀장 PC에서 쓴 메모가 팀원 PC에 뜨고 서로 오간다. 새 메모·새 답글은 하이웍스 메신저 알림으로도 알린다(알림 연동 단계). 엑셀은 백엔드에서 진짜 엑셀 파일로 만든다. 본부 직속(팀 없는) 직원의 확인 메모는 본부장이 쓰게 한다.

### 검증

- `kvSelfCheck()` (index.html 내장, 브라우저 콘솔에서 실행): 기대 진행률 계산(윤년 포함), 부진·갱신 필요 경계값, 직책별 열람 범위, 확인 메모를 쓰는 사람·메모에서의 자리(본인/쓴 사람/보기만)·확인·답글·당일 수정, 알람을 끈 항목을 뺀 계산·고른 달 말일까지·입력 검사, HR 확인을 담당자·팀장이 나눠 하는 규칙, 가중치 합 100, 조직도와 같은 본부·부서 구성.
- 역할 일곱 개 × 모든 메뉴·탭을 돌려 화면이 깨지지 않는지 확인.

## 8. 평가 진행 · 평가 결과 (2026-10-13 개편, 인사담당자 확정)

5장의 평가 루트와 [2026-08-24 백엔드 설계](2026-08-24-hr-evaluation-contract-design.md) 2장의 일부를 바꾼다. 화면(`public/index.html`의 `ev*`)에는 반영했고, 백엔드 도메인(`backend/hr_eval`)은 로그인·DB를 붙일 때 이 장에 맞춘다.

### 누가 평가받나

| 대상 | 평가 | 비고 |
|---|---|---|
| 본부 팀원 (현장직 포함) | 받는다 | |
| 팀장 (본부 · 직속부서) | 받는다 | |
| 직속부서 팀원 (HR 담당자 등) | 받는다 | |
| **본부장** | **받지 않는다** | KPI(본부 KPI)는 계속 쓴다. 포털 연봉계약서 대상에서도 뺀다 |
| 대표이사 | 받지 않는다 | KPI도 없다 |

### 순서 — 묶음마다 누가 하나

등급 비율을 함께 쓰는 **묶음**이 셋이다. 팀별로는 나누지 않는다.

| 묶음 | 1 자기평가 | 2 평가 (점수 + 등급 의견) | 3 등급 배정 | 4 대표이사 확인 | 5 HR 확정 |
|---|---|---|---|---|---|
| 본부 팀원 (본부마다, 팀장·본부장 제외) | 본인 | 팀장 | 본부장 — 팀장 점수도 고칠 수 있다. 전원에게 등급이 있고 정원을 넘지 않아야 마감 | 대표이사 — 직접 고치지 않고, 바꿀 것이 있으면 이유를 적어 본부장에게 돌려보낸다 | HR |
| 전사 팀장 | 본인 | 본부장이 점수와 등급을 함께 (직속부서 팀장은 대표이사) | (2단계에 포함) | 대표이사 — 전사 팀장의 비율을 맞춘다. 등급과 점수를 고칠 수 있다 | HR |
| 직속부서 팀원 | 본인 | 팀장 (HR 담당자는 HR 팀장) | 대표이사 | 대표이사 | HR |

- 현장직(KPI 없음)은 자기평가 없이 팀장이 등급 의견을 내고, 본부 팀원 묶음에서 함께 배정한다.
- 대표이사 확인과 HR 확정은 **묶음째로** 한다. 목록에서 묶음을 체크해 한 번에 넘긴다.
- 본부장이 마감하면 HR에게 알림이 뜨고, 대표이사에게는 "확인할 묶음"으로 뜬다.
- HR은 결과 공개 전까지 묶음을 한 단계 되돌릴 수 있다(기록을 남긴다).
- 평가자가 비는 경우(팀장이 없는 팀의 팀원, 팀 없이 본부장 바로 아래 있는 직원)는 **한 단계 위**(본부장, 본부장도 없으면 대표이사)가 평가한다.

### 등급

| 항목 | 규칙 |
|---|---|
| 점수 | 평가자가 KPI 항목마다 고른 등급(S 110% · A 100% · B 90% · C 80% · D 70%) × 가중치의 합. 가점 0~10점(사유 필수), 총점 상한 110 |
| **2026-10-27 바뀜 — 가점** | **가점은 없다**(본부장 · 대표이사 · 팀장 평가 모두). 연봉 계산의 개인 포상 · 자격증 추가 인상률과 중복 혜택이라서(인사담당자). 총점 = 실행목표 등급 × 가중치의 합이고 상한 110은 그대로다(전부 S면 110). 본부장 · 대표이사가 팀장 점수(실행목표 등급)를 직접 고치는 것은 그대로다. 위 "가점 0~10점" 글은 옛 규칙이다 |
| **점수 기준** | 그 총점으로 받을 수 있는 가장 높은 등급: **S 100 초과 · A 90 초과 · B 80 초과 · C 70 초과 · D 70 이하** (HR이 바꿀 수 있다. 합계에 소수점이 나올 수 있어 기준을 '넘으면' 윗등급이다 — 90.5점은 A, 딱 90점은 B). 그보다 높은 등급은 줄 수 없고(올리려면 점수를 고친다), 비율 때문에 낮게는 줄 수 있다. 평가자가 채점을 마치면 점수에 맞는 등급이 자동으로 나온다. 현장직은 점수가 없어 해당하지 않는다 |
| 정원 | 묶음 인원 N ≥ 5: A·B·D 각 N×10%(0.5는 올림), C 나머지 / N ≤ 4: A·B 합계 1명(N ≥ 2), 나머지 C·D. S를 준 만큼 A가 줄어든다. 초과는 막고 미달은 경고만 |
| **2026-10-27 바뀜 — 정원 비율** | 정원 비율은 고정 10%가 아니라 **HR이 해마다 정한다**: S·A · B · D 각각 묶음 인원의 %(정수 0~70, 세 칸 합 70 이하, 처음 10 · 10 · 10, C는 나머지). 모든 묶음에 같은 비율이고 N ≥ 5일 때만 쓴다(0.5 올림도 N ≤ 4 규칙도 그대로). 진행표 기준 점수 밑에서 [마감일 저장]으로 함께 저장하고, 평가를 시작하면 바꿀 수 없다 |
| **2026-10-27 바뀜 — 대표이사 정원 예외** | 대표이사가 그해 한 묶음의 정원을 **늘려 줄 수 있다**(S·A 쪽 · B 쪽 각 0~5명, 이유 1~200자). 본부 팀원 묶음은 본부장에게 돌려보낼 때 함께 보내고, 대표이사가 직접 등급을 정하는 묶음(전사 팀장 · 직속부서 · 본부장 없는 본부)은 자기 배정 화면에서 바로 늘린다(맡겼으면 HR이 대신 — 자기가 든 묶음은 못 한다). 점수 기준과 연차 규칙은 예외로도 넘지 못한다. 늘린 정원과 이유는 본부장 화면 · HR 화면 · 결과 보고서에 보이고, 대표이사 확인을 마친 묶음과 공개 뒤에는 늘릴 수 없다 |
| **2026-10-27 바뀜 — D 정원** | D 정원은 **본부장이 점수보다 낮춰 D를 줄 수 있는 최대 인원**이다. 총점이 C 기준 이하라 점수로 D밖에 받을 수 없는 사람은 D 정원에 세지 않는다(그래서 점수로 D인 사람이 D 정원보다 많아도 마감된다 — D 비율 0이어도 같다). 미달 경고("D가 정원보다 n명 적습니다")는 점수로 D인 사람까지 모두 센다. 위 정원 줄의 "초과는 막고"는 이 뜻으로 읽는다 |
| **2026-10-27 바뀜 — 점수 역전** | 점수가 더 낮은 사람이 더 높은 등급을 받으면 알린다. 점수가 더 높은데 등급이 낮은 사람(그 등급을 받을 수도 있었던 사람 — 점수 기준 · 연차 규칙 안)에게는 **윗사람 코멘트(이유)가 꼭 있어야** 본부 팀원 · 직속부서 팀원 묶음을 마감하고 대표이사가 확인할 수 있다(전사 팀장 묶음은 경고만). 동점 · 점수 없음(현장직) · 연차 때문에 그 등급을 못 받는 경우는 역전이 아니다. 이유(윗사람 코멘트)는 마감 전 대표이사 · HR이 보고, 결과 공개 뒤 그 직원에게도 보인다 |
| **2026-10-27 바뀜 — 등급 안내** | 직원의 자기평가 · 결과 화면에 "등급은 점수 기준과 정원으로 정해요(점수 기준은 받을 수 있는 가장 높은 등급)"를, 결과 화면에는 "점수로는 A까지 가능했고, 본부 정원에 따라 C로 정해졌어요" 한 줄을 보인다. 팀장(평가자) 점수 화면에는 그해 정원과 "최종 등급은 본부장이 본부 정원 안에서 정해요. 등급 의견은 점수로 받을 수 있는 가장 높은 등급이에요"를 보인다 |
| **2026-10-28 바뀜 — 팀장 채점 성향** | 전사 팀장 묶음만, 평가자(본부장 · 직속부서 팀장은 대표이사)마다 **낸** 점수로 채점 성향을 본다(인사담당자 — 본부장이 다 높게 채점해 보내면 대표이사의 주관이 커진다는 걱정, 본부장 순위는 한 본부 팀장이 2~4명이라 뺐다). ① 대표이사 · HR의 전사 팀장 명단 위 **평가자 채점 성향 표**: 채점한 팀장 수 · 평균 총점 · 전사 평균과 차이(5점 이상 '높게 줌' · −5점 이하 '낮게 줌') · 실행목표 등급 중 S·A 비율 · 전사 줄. ② 팀장마다 **보정 점수** = 총점 − (그 평가자 평균 − 전사 평균) · [총점 순 / 보정 점수 순]. ③ 추천 등급은 채우지 않는다(등급은 대표이사). ④ 본부장은 팀장 점수 화면에서 **자기 성향 한 줄만** 본다(다른 본부 숫자는 공개 전 · 뒤 모두 안 보임). ⑤ 전사 팀장 묶음의 점수 역전 경고는 **보정 점수로 비교**한다(경고만). 정한 것: 셈은 전사 팀장 묶음만 · 대표이사가 고친 점수는 성향에 안 든다 · 기준 5점 · 줄 수 있는 가장 높은 등급(점수 기준 · 연차)은 총점으로. 서버 응답에 새 칸은 없다(화면이 받는 줄로 센다) |
| **연차 초과** | 연차를 5일 이상 초과 사용하면 S·A·B 불가 — **평가받는 모든 사람**(처음에는 현장직만이었다). HR이 전 직원의 연차 초과일을 넣는다. 지각 횟수는 현장직만 넣고 참고만 한다 |
| 근태 잠금 | 그 사람의 등급이 다음 단계로 넘어가면 근태를 고칠 수 없다. 고치려면 먼저 되돌린다 |

### 기간

| 항목 | 규칙 |
|---|---|
| 단계별 마감일 | HR이 진행표에서 평가 시작일과 자기평가 · 평가자 평가 · 등급 배정 · 대표이사 확인 · HR 확정의 마감일을 정한다 |
| 마감일이 지나면 | **자기평가만 막는다.** 나머지 단계는 지나도 할 수 있고 본인 화면과 HR 진행표에 "기한 지남"으로 표시한다 |
| 자기평가 | 제출 전에 "고칠 수 없다"는 안내 창이 뜨고, 낸 뒤에는 고칠 수 없다. 마감일까지 못 낸 사람은 HR이 "자기평가 없이 진행"으로 넘긴다 |
| 평가에서 제외 | 수습·휴직처럼 평가하지 않는 사람은 HR이 뺀다(평가자가 점수를 내기 전에만). 묶음 인원과 비율에서도 빠진다 |
| 증빙 | 평가 시작 ~ 증빙 마감일, 평가자가 점수를 내기 전까지 |
| 근태 안내 | 평가가 시작되면 HR 진행표에 "연차 초과일과 지각 횟수를 넣어 주세요"가 뜬다. HR이 "마쳤습니다"를 누를 때까지 남는다 |

### 공개 전에 보이는 것

| 보는 사람 | 결과 공개 전 |
|---|---|
| 본인 | 자기가 낸 자기평가만. 점수·등급은 HR이 공개해야 보인다 |
| 평가자 (팀장 · 팀장을 평가한 본부장) | **자기가 낸 점수와 등급 의견만.** 윗사람이 고치면 "고쳤습니다"만 알리고, 무엇이 바뀌었는지는 공개 뒤에 보인다 |
| 등급을 정하는 사람 (본부장 — 자기 본부 팀원) | 본다 |
| 대표이사 · HR | 본다 (HR 담당자·HR 팀장은 본인 것도 보인다 — 인사담당자 결정) |

### 대표이사의 일을 HR이 대신 할 때

대표이사가 포털에서 **"HR에 맡기기"** 를 켜야 한다. 켜져 있는 동안 HR 담당자·HR 팀장이 대표이사의 일(직속부서 팀장 평가 · 등급 조정 · 확인 · KPI 승인 · 이의 신청 확인)을 대신 넣는다. 넣은 사람 이름이 "대리 입력"으로 남고, HR 본인의 것은 대신 넣을 수 없다.

### 평가 결과 · 이의 신청 · 연봉계약서

| 항목 | 규칙 |
|---|---|
| 결과 공개 | 모든 묶음이 HR 확정까지 끝나야 HR이 공개한다. 전 직원이 같은 날 본다 |
| 이의 신청 | 공개일부터 7일, 1회, 사유 필수 (그대로) |
| 답변 | HR이 답변한다. 등급을 **유지**하면 바로 직원에게 간다. 등급을 **바꾸면 대표이사가 확인**해야 반영된다(동의하지 않으면 HR로 돌려보낸다) |
| 등급 변경의 조건 | 정원은 따지지 않는다(이미 공개된 다른 사람의 등급을 건드릴 수 없다). 점수 기준과 연차 규칙은 지킨다 — 올리려면 답변에서 항목 점수를 함께 고친다 |
| 결과를 보는 범위 | 본인 = 내 결과 / 팀장 = 자기 팀원 / 본부장 = 자기 본부 / 대표이사 = 전체 / HR = 전체 |
| 연봉계약서 | 평가받는 사람은 결과가 공개되고 이의 신청 처리가 끝나야 발송한다. 보낸 뒤 등급이 바뀌면 HR에게 "다시 보내야 함"을 표시한다. 본부장·대표이사는 포털 계약서가 없다 |

### HR 화면

HR 담당자·HR 팀장의 평가·성과 화면은 둘로 나뉜다: **내 KPI · 평가**(본인 것 — KPI 작성, 자기평가, HR 팀장의 팀원 평가)와 **직원 인사평가 관리**(기간 · 진행표 · 확정 · 명단과 근태 · 결과 공개 · 이의 신청 · 대표이사가 맡긴 일).

### 규칙만 정하고 아직 만들지 않은 것

1. 구성원 설정의 "평가 대상"을 끈 사람을 평가 명단에서 자동으로 빼기 — 조직도 명단과 평가 명단이 하나로 합쳐지는 로그인·DB 이후. 그 전에는 HR이 평가 명단에서 제외한다.
2. 평가자가 비는 경우를 명단에서 자동으로 찾기 — 시연 명단에는 해당자가 없다.
3. 중도 입사자는 HR이 그 사람에게 작성 기간을 열어 KPI를 쓰고, 연중에 부서를 옮긴 사람은 평가 시작일의 소속을 기준으로 평가자를 정한다.
4. 인원이 적은 묶음(1~4명)의 정원은 그대로 둔다.

### 검증

`evSelfCheck()` · `evLineSelfCheck()` · `evrSelfCheck()` (index.html 내장): 묶음과 평가자, 점수 기준, 연차 규칙, 단계별 마감일, 근태 잠금, 공개 전 숨김, 대표이사 확인 → HR 확정 · 돌려보내기 · 되돌리기, 평가 제외, 윗사람 수정 알림, 이의 신청(대표이사 확인 · 점수 고치기), 계약서 반영.
