# 평가·성과 > 목표설정(KPI) 화면 설계

- 작성일: 2026-09-21
- 상태: 인사담당자 승인됨 (화면 먼저, 실제 저장은 로그인 모듈 이후)
- 업무 규칙의 원본: [2026-08-24-hr-evaluation-contract-design.md](2026-08-24-hr-evaluation-contract-design.md) 2장. 이 문서는 그 규칙을 화면으로 옮긴 것이며 규칙을 바꾸지 않는다.

## 1. 한 문장 정의

직원이 그해 KPI를 엑셀 양식(`2025년 개인 KPI_부서_이름.xlsx`)과 같은 구조로 입력하고, 팀장·본부장 승인을 받아 확정하며, 정해진 기간에만 수정을 요청할 수 있는 화면.

## 2. 화면 구성

| 영역 | 내용 |
|---|---|
| 시연용 역할 전환 | 직원 / 팀장 / 본부장 / HR 버튼. **로그인이 생기면 제거한다.** |
| 내 KPI | 팀목표 → 개인목표 → 실행목표(행) 구조. 열: 실행목표, 측정식, 가중치, 담당자, S(110%)·A(100%)·B(90%)·C(80%)·D(70%) 달성 기준, **맨 우측 증빙자료** |
| 승인 대기함 | 팀장·본부장·HR. 기존 KPI와 제출안을 위아래로 비교, 바뀐 행 강조. 승인 / 반려(사유 필수) |
| HR 패널 | ① KPI 작성·수정 기간 ② 평가 기간(증빙 업로드)을 날짜로 설정. 전 직원 진행현황 표 |
| 작성 방법 | 엑셀 하단 SMART 안내문을 접이식 도움말로 |

## 3. 규칙

| 항목 | 규칙 |
|---|---|
| KPI 개수 | 실행목표(가중치가 붙는 행) **최소 3개, 상한 없음**. 목표·행 추가/삭제 자유 |
| 가중치 | 각 행 0 초과, **전체 합 정확히 100**. 아니면 제출 버튼 비활성 |
| 작성·수정 기간 | HR이 시작일~종료일 지정. **기간 밖에서는 입력·버튼 전부 비활성(조회만)** |
| 최초 작성 | 작성중 → 제출 → 1차 팀장 → 2차 본부장 → 확정(잠금) |
| 수정 | 확정 후 수정 기간에만 "수정 요청"(사유 필수) → 1차 팀장 → 2차 본부장 → 반영. **승인 전까지 기존 KPI 유효**, 반려 시 기존 유지. 미결 요청은 1인 1건 |
| 결재선 예외 | 팀장 본인: 본부장 1단계. 본부장 본인: HR 1단계. 팀 없는 본부 직속: 본부장 1단계 |
| 증빙 업로드 | **평가 기간에만**, 확정된 KPI의 행별로. 승인 불필요. PDF·이미지·엑셀·워드·한글, 파일당 10MB |
| 담당자명 | 본인 이름 자동 입력(수정 가능) |

## 4. 이번 범위 / 나중

**이번**: `public/index.html`의 `comingSoon` 자리를 교체. 데이터는 브라우저 메모리의 가상 직원 4명(새로고침 시 초기화). 파일은 이름만 표시하고 서버로 보내지 않는다.

**나중(로그인·DB 이후)**: 실제 저장(`backend/hr_eval`의 `submit_kpi_goal`·수정 요청 유스케이스에 연결), 증빙 파일 서버 보관(공개 저장소 밖, 서버 내부 폴더), 서버 측 파일 형식·크기 검증, 역할 전환 버튼 제거.

## 5. 다음 메뉴(평가 진행)에서 쓸 평가 루트 — 방향만 합의

① 본인 자기평가(실적·증빙·자가 등급) → ② 1차 팀장: 항목별 등급 확정, 점수 = Σ(가중치 × 등급%) → ③ 2차 본부장: 본부 정원 규칙에 따라 최종 등급 배정, 가점은 사유 필수 → ④ HR 검수·확정·공개.
엑셀의 S 110%가 기존 "총점 상한 110점"과 일치한다.

## 6. 검증

- `kpiSelfCheck()` (index.html 내장, 브라우저 콘솔에서 실행): 개수·가중치 검증, 기간 판정, 2단계 승인·반려·결재선 예외.
- 로컬 http 서버로 띄워 역할을 바꿔가며 클릭 검증: 작성→승인→잠금 / 기간 밖 비활성 / 수정 요청→반려·승인 반영 / 평가 기간 업로드.
