## 1. 발급 전에 정해야 할 것 — 두 번 일하지 않기 위한 체크리스트

오피스 토큰은 **다시 만들면 기존 연결이 즉시 끊긴다** (매뉴얼 명시). 매뉴얼에는 발급 후 Scope·IP를 고칠 수 있는지 나와 있지 않다. 따라서 **아래 항목을 모두 정한 뒤 한 번에 발급**한다.

| # | 항목 | 정하는 사람 | 발급 전 필수 | 틀리면 생기는 일 |
|---|---|---|---|---|
| A | 가비아 회신 확인 — **완료** (0장 표): 요금 없음, 근태 조회 불가, OAuth 불가, 테스트 환경 없음. 조직 조회·직급·토큰 유효기간·발급 후 Scope/IP 수정 가능 여부는 **재문의 없이** 발급 후 실측 또는 미확인으로 둔다 | 인사담당자 | ✅ 완료 | 발급 후 Scope·IP 수정 가능 여부를 모르므로, C·D는 **한 번에 맞게** 정해야 한다 |
| B | **하이웍스 API 담당자**가 누구인지, 그 사람이 **슈퍼 관리자 계정**을 쓸 수 있는지 | 인사담당자 | ✅ | 토큰·SSO·메뉴 등록을 할 수 없다 |
| C | **포털 서버가 연결된 회선의 공인 IP** (회사 대표 주소. 사내 `192.168.x.x` 같은 내부 IP가 아님) + **고정 IP인지** | 하이웍스 API 담당자 (사내망 담당, 직접 확인) | ✅ | IP 없이 발급하면 토큰이 어디서든 쓰일 수 있다. 유동 IP면 IP가 바뀌는 순간 연결이 막힌다. **IP는 공개 저장소·이슈에 적지 않는다** |
| D | 켤 Scope 확정: **요금이 없는 기능은 모두 켠다** (아래 "1장 D 참고" 표). 단 **회계지원은 하이웍스 API 담당자가 발급 전 인사담당자와 협의해 선택** | 하이웍스 API 담당자 · 인사담당자 | ✅ | 빠뜨리면 나중에 추가하려고 재발급 → 연결 끊김 |
| E | SSO 연동 URL 확정: `https://hr.abyz-lab.work/api/auth/hiworks` | 개발 | ✅ (SSO 등록 전) | URL이 바뀌면 SSO 등록을 지우고 다시 해야 한다 (삭제 시 그 URL을 쓰는 연동 전부 해제) |
| F | 토큰 전달 경로: 하이웍스 API 담당자 → 서버 `.env`까지 **글로 남지 않는 방법** (직접 입력 또는 대면 전달). 하이웍스 API 담당자는 GitHub 권한이 없으므로 서버 반영은 GitHub 저장소 소유자가 한다 | GitHub 저장소 소유자 · 하이웍스 API 담당자 | ✅ | 메일·메신저·이슈에 남으면 유출로 보고 재발급해야 한다 |
| G | 테스트 대상: 알림·결재 테스트를 받을 계정 (실제 직원에게 가지 않도록). **가비아가 테스트 환경을 제공하지 않으므로 필수** | 인사담당자 | ✅ 연동 테스트 전 필수 | 테스트 알림·결재가 실제 직원에게 나간다 |
| H | 포털 역할 연결 규칙: 누가 포털 HR 권한자인지, 팀장·본부장을 무엇으로 구분하는지 (5장 조직 조회 실측 결과에 따라) | 인사담당자 | 로그인 구현 전 | 권한이 잘못 부여된다 |
| I | KPI 승인용 전자결재 양식 | 인사담당자 · 하이웍스 API 담당자 (슈퍼 관리자 또는 전자결재 관리자 계정) | 결재 연동 전 | 없으면 결재 연동을 할 수 없다 (토큰과는 무관, 나중에 해도 됨) |

**발급 가능 조건: A~F 완료.** G~I는 발급 후에 해도 토큰을 다시 만들 일이 생기지 않는다 (G는 첫 테스트 전까지).

### 1장 C 참고 — 어떤 IP인가

| 구분 | 설명 | 등록 대상 |
|---|---|---|
| 내부 IP (`192.168.x.x`, `10.x.x.x` 등) | 사내 내선번호에 해당. 회사 밖(하이웍스)에서는 보이지 않는다 | ❌ |
| **공인 IP** | 회사 대표번호에 해당. 포털 서버가 하이웍스에 요청하면 하이웍스에는 이 주소만 보인다 | ✅ |
| Cloudflare 터널 주소 | 포털로 **들어오는** 경로다. 하이웍스로 **나가는** 요청과 무관하다 | ❌ |

- 확인: 하이웍스 API 담당자가 공유기·회선 정보에서 확인한다. 포털 서버에서 `curl -s https://api.ipify.org`를 실행해 나오는 주소와 같아야 한다.
- 사무실 회선을 같이 쓰면 사무실 전체가 같은 공인 IP다. 제한 범위가 "서버"가 아니라 "사무실"이 되지만, 외부 유출 대비 효과는 있다.
- 유동 IP면 고정 IP 신청 또는 IP 변경 시 재등록 절차를 먼저 정한다.

### 1장 D 참고 — 켤 기능 (토큰 생성 화면의 Scope 8개)

원칙: 나중에 켜려면 재발급(연결 끊김)이 필요하므로, **요금이 없는 기능은 처음부터 모두 켠다.** 건당 요금이 나가는 기능은 유출·오작동 시 실제 비용이 청구되므로 켜지 않는다.

| Scope | 요금 | #42 계획에서 쓰는 곳 | 결정 |
|---|---|---|---|
| 인사 (조직 조회 / 캡스 연동) | 없음 | 조직도·직원 명단 (조회 가능 여부는 발급 후 실측). 근태는 가비아 회신상 불가 | ✅ **켬** (실측 결과 조회가 안 돼도 켜 둔 비용이 없고, 되면 재발급 없이 쓴다) |
| 전자결재 (기안하기 / 문서 조회) | 없음 | KPI 승인, 연봉계약 확정, 증명서 신청 | ✅ **켬** |
| 알림 (메신저 알림) | 없음 | KPI 작성 기간·승인 요청·계약서 서명 요청·자격 만료 알림 | ✅ **켬** |
| 이메일 (이메일 보내기) | 없음 | 알림 보조 수단 | ✅ **켬** |
| 회계지원 (회계 정보) | 없음 | 계획에 없음. 향후 출장·경비 정산 연동 가능성 | ⚠️ **하이웍스 API 담당자가 발급 전 인사담당자와 협의해 선택** |
| 문자 (문자 조회 / 문자 발송) | 건당 과금 | 제외 (#42: "메신저 푸시 위주") | ❌ 끔 |
| 카카오 알림톡 (조회 / 발송) | 건당 과금 | 제외 | ❌ 끔 |
| 전자세금계산서 | 발급 건당 과금, 별도 키 필요 | 해당 없음 | ❌ 끔 |

회계지원 협의 시 참고:

| 켤 때 | 켜지 않을 때 |
|---|---|
| 향후 경비 정산 연동 시 재발급이 필요 없다 | 토큰이 유출돼도 회사 지출·송금 데이터(지출결의)는 드러나지 않는다 |
| IP 제한(1장 C)으로 유출 위험은 낮아진다 | 나중에 필요해지면 재발급(연결 끊김)이 필요하다 |

## 2. 하이웍스 API 담당자가 할 설정 — 회차별

하이웍스 관리 화면에서 하이웍스 API 담당자가 직접 한다. 대부분 **슈퍼 관리자 계정**이 필요하다. 작업은 아래 회차로 끝난다. 하이웍스 API 담당자는 GitHub 권한이 없으므로, 각 회차가 끝나면 **인사담당자에게 알리고 인사담당자가 #42에 기록**한다.

### 1회차 — 발급일 (1장 발급 가능 조건 충족 후)

| 순서 | 메뉴 경로 | 할 일 |
|---|---|---|
| 1 | `login.office.hiworks.com/회사도메인` 로그인 → [오피스관리] | 슈퍼 관리자 계정으로 진입 |
| 2 | [서비스 연동(API) > 오피스 연동 > 서비스 연동] → [오피스 토큰 생성] | ① 토큰 이름 (예: 인사포털) ② Scope: **1장 D 표대로** — 인사·전자결재·알림·이메일 켬, 회계지원은 협의 결과대로, 문자·카카오 알림톡·전자세금계산서 끔 ③ **IP: 1장 C에서 확인한 공인 IP 등록** ④ [저장] |
| 3 | [서비스 연동(API) > SSO 관리 > 외부로 연동] → [연동 추가] | 1장 E의 URL을 그대로 등록 |
| 4 | 토큰 전달 | 1장 F에서 정한 방법으로 GitHub 저장소 소유자에게 전달해 서버 `.env`에만 넣는다. **채팅·이슈·메일에 적지 않는다**. 완료 사실만 인사담당자에게 알린다 |

### 2회차 — 개발 쪽이 "로그인 준비 완료"를 알린 뒤

| 순서 | 메뉴 경로 | 할 일 |
|---|---|---|
| 5 | [환경 설정 > 메뉴 설정 > 인트라넷 메뉴 설정 > 인트라넷 메뉴 추가] | 3에서 만든 SSO를 골라 "인사포털" 메뉴 추가. 먼저 하면 직원이 눌렀을 때 오류 화면이 나온다 |

### 필요할 때 — 결재 양식 내용이 확정될 때마다 (토큰 재발급과 무관)

| 순서 | 메뉴 경로 | 할 일 | 권한 |
|---|---|---|---|
| 6 | [전자결재 > 관리자 설정 > 양식함 관리] | 양식(KPI 승인부터)을 만들거나 고른 뒤 상세 페이지 상단의 **양식 아이디** 확인. 선택: [양식 수정]에서 "작성 페이지 및 팝업에서 사용 불가" 체크 시 외부 연동 전용 양식이 된다 | 슈퍼 관리자 계정 또는 전자결재 관리자 계정 |
| 7 | 양식 아이디 전달 | GitHub 저장소 소유자에게 전달해 서버 `.env`에 추가 (양식 아이디는 비밀값은 아니나 같은 경로로 전달) | — |

주의 (매뉴얼 명시):
- 오피스 토큰은 "그룹웨어 전체를 관리하는 인증키"다. 비밀번호처럼 다룬다.
- **토큰을 재발급하면 기존 연동은 더 이상 동작하지 않는다.** 재발급하면 서버 `.env`도 즉시 교체해야 한다.
- 등록된 SSO 연동을 삭제하면 그 연동 URL을 쓰는 모든 사이트의 연동이 풀린다.
- "지출 결의서" 양식은 현재 연동할 수 없다.

## 3. 개발 쪽 착수 준비 — `.env`만으로는 착수할 수 없다

### 결재 양식 아이디 이름 규칙

결재 종류마다 하이웍스 양식이 하나씩 있고, 양식마다 아이디가 하나씩 생긴다. **결재 종류 하나 = `.env` 변수 하나**로 둔다.

| 규칙 | 내용 |
|---|---|
| 형식 | `HIWORKS_FORM_ID_<결재 종류>` — 결재 종류는 영어 대문자·밑줄 |
| 값 | 하이웍스 [전자결재 > 관리자 설정 > 양식함 관리] → 양식 상세 상단의 양식 아이디 (2장 6번) |
| 추가 시점 | 그 결재를 연동하는 **구현 PR에서** 변수 이름을 정하고 `.env.example`·`docker-compose.yml`·코드에 같은 이름으로 넣는다. 이 표에도 한 줄 추가한다 |
| 비어 있을 때 | 그 결재 기능만 꺼진 상태로 동작해야 한다 (다른 결재와 무관) |

예시 (확정 아님 — 구현 PR에서 확정 후 이 표를 고친다):

| 결재 | 변수 이름 (예시) | 상태 |
|---|---|---|
| KPI 승인 | `HIWORKS_FORM_ID_KPI` | 미구현 |
| 연봉계약 확정 | `HIWORKS_FORM_ID_CONTRACT` | 미구현 |
| 증명서 신청 | `HIWORKS_FORM_ID_CERT` | 미구현 |

## 5. 기능별 동작 흐름

### 로그인 (SSO, "외부로 연동")
1. 직원이 하이웍스 화면에서 "인사포털" 인트라넷 메뉴를 누른다.
2. 하이웍스가 `등록한 연동 URL?token={token}`으로 보낸다.
3. 서버가 link-api로 token을 조회해 user-no·아이디·이름·사번을 받는다.
4. 서버가 포털 세션을 발급한다.

출입구는 **하이웍스 메뉴**다. 포털 주소로 바로 들어온 사람은 하이웍스로 안내해야 한다 (#42 댓글 ⑤ 참고). 포털 화면에서 시작하는 로그인(OAuth)은 지원이 중단되었다.

### 조직도
토큰 발급 직후 `GET /hrm/v2/organizations`, `GET /hrm/v2/users`를 1회 호출해 **조회 가능 여부를 판정**한다 (가비아 회신은 "넣는 방향만 가능", API 문서는 조회 API 존재 — 0장).

| 실측 결과 | 방식 |
|---|---|
| 조회됨 | 서버가 하루 1회 조직도·사용자를 가져와 저장하고, 화면은 저장본을 쓴다. 직급이 응답에 없으면 직급만 포털에서 입력한다 |
| 조회 안 됨 | **HR이 포털에 직원 명단을 직접 입력**한다 (현재 조직도 화면의 HR 등록 기능 유지). 로그인한 사람과 명단은 SSO가 주는 **사번(employee-no)**으로 연결한다 |

어느 쪽이든 로그인(SSO)은 동작한다. 조회 불가 시 #42의 "HR이 두 군데 입력하지 않음" 목표는 달성되지 않는다.

### 전자결재 (KPI 승인 등)
1. 포털에서 [결재 올리기]를 누른다.
2. 서버가 기안 API를 호출해 `login_url`을 받는다.
3. 브라우저가 `login_url`을 팝업으로 연다. 하이웍스 로그인 후 내용이 채워진 기안 문서가 열린다.
4. **직원이 결재선을 지정하고 [기안하기]를 누른다** (완전 자동 상신이 아니다).
5. 상태가 바뀔 때마다 하이웍스가 `callback_url`로 GET 요청을 보낸다.
   `office_id, approval_key, approval_id, approval_code, state, request_hash`
   state 값: `progress`(기안) / `rejected`(반려) / `canceled`(기안 취소) / `complete`(결재 완료) / `deleted`(삭제)

### 알림
서버가 알림 발송 API에 받는 사람 아이디 목록, 메시지, 누르면 이동할 링크를 담아 호출한다.

## 6. 리스크와 대응

| 리스크 | 근거 | 대응 |
|---|---|---|
| **결재 콜백 위조 가능** | `request_hash`는 서명이 아니라 기안할 때 넣은 `state` 값을 그대로 돌려주는 값이다 | 콜백을 받으면 **문서 상태 조회 API로 실제 상태를 다시 확인**한 뒤 반영한다. `state`에는 추측하기 어려운 무작위 값을 넣어 요청과 대조한다 |
| 오피스 토큰 권한이 크다 | 매뉴얼: "그룹웨어 전체를 관리하는 API 인증키" | 과금 Scope(문자·알림톡·세금계산서)는 켜지 않고, IP 제한을 반드시 적용한다. `.env`에만 보관한다 |
| 토큰 재발급 시 연동 중단 | 매뉴얼 명시 | 재발급과 `.env` 교체를 같은 날 함께 한다 |
| 호출 한도 하루 1,000건 | 오피스(회사) 단위, 성공한 호출 기준 | 조직도는 하루 1회만 가져온다. 알림은 user_list로 묶어 보낸다 |
| SSO 토큰 유효시간·1회용 여부 | **문서에 없음** | 실제 연결 테스트로 확인한다 |
| **조직 조회 가능 여부** | 가비아 회신(넣기만 가능)과 API 문서(조회 API 존재)가 어긋남 | 발급 직후 실측으로 판정. 불가 시 HR 포털 입력 + 사번 연결 (5장) |
| 직급·직위 정보 | 조회 응답 예시에 **없음** | 포털에서 직급을 따로 입력받는다 |
| 토큰 유효기간 | 가비아 **미답변**, 문서에 없음 | 연결 실패 시 토큰 만료부터 의심하도록 오류 기록에 남긴다 |
| 테스트 환경 없음 | 가비아 회신 | 테스트 계정(1장 G)으로만 알림·결재를 시험한다 |
| 근태 조회 | 가비아 회신: **불가** | 계획에서 제외 |
| 요금제 조건 | 문서에 없음 → 가비아 회신: **API 별도 요금 없음** (0장) | 해결 |
