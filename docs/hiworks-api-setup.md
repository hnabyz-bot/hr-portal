## 1. 발급 전에 정해야 할 것 — 두 번 일하지 않기 위한 체크리스트

오피스 토큰은 **다시 만들면 기존 연결이 즉시 끊긴다** (매뉴얼 명시). 매뉴얼에는 발급 후 Scope·IP를 고칠 수 있는지 나와 있지 않다. 따라서 **아래 항목을 모두 정한 뒤 한 번에 발급**한다.

| # | 항목 | 정하는 사람 | 발급 전 필수 | 틀리면 생기는 일 |
|---|---|---|---|---|
| A | 가비아 문의 결과: 요금제에 Open API 포함 여부, 직원 목록에 직급 포함 여부, 근태(캡스) 조회 가능 여부 | 인사담당자 | ✅ | API를 못 쓰는 요금제면 발급 자체가 의미 없다 |
| B | 하이웍스 **전체(슈퍼) 관리자**가 누구인지 | 인사담당자 | ✅ | 토큰·SSO·메뉴 등록을 할 수 없다 |
| C | **포털 서버의 외부 출구 IP** | 개발 → 관리자에게 전달 | ✅ | IP 없이 발급하면 토큰이 어디서든 쓰일 수 있다. 나중에 넣으려다 재발급이 필요하면 연결이 끊긴다. **IP는 공개 저장소·이슈에 적지 않고 관리자에게 직접 전달한다** |
| D | 켤 Scope 확정: **인사(조직 조회), 알림(메신저 알림), 전자결재(기안하기/문서 조회)** 3개. 결재 연동은 나중이어도 **지금 같이 켠다** | 개발 제안 · 관리자 확인 | ✅ | 빠뜨리면 나중에 추가하려고 재발급 → 연결 끊김 |
| E | SSO 연동 URL 확정: `https://hr.abyz-lab.work/api/auth/hiworks` | 개발 | ✅ (SSO 등록 전) | URL이 바뀌면 SSO 등록을 지우고 다시 해야 한다 (삭제 시 그 URL을 쓰는 연동 전부 해제) |
| F | 토큰 전달 경로: 관리자 → 서버 `.env`까지 **글로 남지 않는 방법** (직접 입력 또는 대면 전달) | 저장소 소유자 · 관리자 | ✅ | 메일·메신저·이슈에 남으면 유출로 보고 재발급해야 한다 |
| G | 테스트 대상: 알림·결재 테스트를 받을 계정 (실제 직원에게 가지 않도록) | 인사담당자 | 연동 테스트 전 | 테스트 알림·결재가 전 직원에게 나간다 |
| H | 포털 역할 연결 규칙: 누가 HR 관리자인지, 팀장·본부장을 무엇으로 구분하는지 (A의 직급 결과에 따라) | 인사담당자 | 로그인 구현 전 | 권한이 잘못 부여된다 |
| I | KPI 승인용 전자결재 양식 | 인사담당자 · 전자결재 관리자 | 결재 연동 전 | 없으면 결재 연동을 할 수 없다 (토큰과는 무관, 나중에 해도 됨) |

**발급 가능 조건: A~F 완료.** G~I는 발급 후에 해도 재작업이 생기지 않는다.

## 2. 하이웍스 관리자가 할 설정 (1장 A~F 완료 후)

하이웍스 관리 화면에서 사람이 직접 한다. 대부분 **전체(슈퍼) 관리자** 계정이 필요하다.

| 순서 | 메뉴 경로 | 할 일 | 필요 권한 |
|---|---|---|---|
| 1 | `login.office.hiworks.com/회사도메인` 로그인 → [오피스관리] | 진입 | 슈퍼 관리자 |
| 2 | [서비스 연동(API) > 오피스 연동 > 서비스 연동] → [오피스 토큰 생성] | ① 토큰 이름 (예: 인사포털) ② Scope: **1장 D의 3개만** 켠다. 이메일·문자·카카오 알림톡·회계지원·전자세금계산서는 켜지 않는다 ③ **IP: 1장 C에서 받은 IP를 등록**한다 ④ [저장] | 슈퍼 관리자 |
| 3 | [서비스 연동(API) > SSO 관리 > 외부로 연동] → [연동 추가] | 1장 E의 URL을 그대로 등록한다 | 슈퍼 관리자 |
| 4 | [환경 설정 > 메뉴 설정 > 인트라넷 메뉴 설정 > 인트라넷 메뉴 추가] | 3에서 만든 SSO를 골라 "인사포털" 메뉴를 추가한다. **개발 쪽이 "로그인 준비 완료"를 알린 뒤에 한다** (먼저 하면 직원이 눌렀을 때 오류 화면이 나온다) | 슈퍼 관리자 |
| 5 | [전자결재 > 관리자 설정 > 양식함 관리] | KPI 승인용 양식을 만들거나 고른 뒤, 상세 페이지 상단의 **양식 아이디**를 확인한다. 선택 사항: [양식 수정]에서 "작성 페이지 및 팝업에서 사용 불가"를 체크하면 외부 연동 전용 양식이 된다 | 슈퍼 관리자 또는 전자결재 관리자 |
| 6 | 토큰·양식 아이디 전달 | 1장 F에서 정한 방법으로 서버 `.env`에만 넣는다. **채팅·이슈·메일에 적지 않는다** | — |

주의 (매뉴얼 명시):
- 오피스 토큰은 "그룹웨어 전체를 관리하는 인증키"다. 비밀번호처럼 다룬다.
- **토큰을 재발급하면 기존 연동은 더 이상 동작하지 않는다.** 재발급하면 서버 `.env`도 즉시 교체해야 한다.
- 등록된 SSO 연동을 삭제하면 그 연동 URL을 쓰는 모든 사이트의 연동이 풀린다.
- "지출 결의서" 양식은 현재 연동할 수 없다.

## 3. 개발 쪽 착수 준비 — `.env`만으로는 착수할 수 없다

2026-09-29 기준 저장소 상태: `backend/`에 로그인·세션 코드가 없고, 사용자 DB는 설계·스키마(`backend/hr_eval/sql/001_init.sql`)만 있다. 로그인 설계([2026-08-24 SQLite 인증 설계](superpowers/specs/2026-08-24-sqlite-auth-design.md))는 아이디·비밀번호 방식 기준이며 "설계 검토 대기" 상태다.

| 새 서버 경로 (예정) | `/api/auth/hiworks` (SSO 수신), `/api/approval/callback` (결재 상태 수신) |

### 사용할 API

| 기능 | 메서드·경로 | 요청 핵심 값 | 응답 핵심 값 |
|---|---|---|---|
| 조직도 조회 | `GET /hrm/v2/organizations` | — | 조직 이름, 소속 구성원(아이디·이름·이메일·전화·휴대폰·user_no) |
| 사용자 조회 | `GET /hrm/v2/users` | — | no, user_id, name |
| 알림 발송 | `POST /office/v2/notify` | user_list, message, link (필수) / solution_name, solution_image_url (선택) | code: SUC |
| 전자결재 기안 | `POST /office/approval/documents` | form_id, subject, contents(html/text), callback_url, modify_contents_flag, modify_files_flag (필수) / files, state (선택) | approval_key, **login_url** (팝업으로 연다) |
| 결재 문서 상태 조회 | `GET /approval/v2/documents/{문서번호}` | — | state |
| SSO 사용자 확인 | `GET link-api …/v4/tokens/{token}` | — | user-no, user-id, user-name, employee-no |

### 사용하지 않을 API

| API | 이유 |
|---|---|
| 조직 연동 `/office/org/*` (직위·직무·조직·구성원 추가/수정/삭제) | 방향이 **포털 → 하이웍스**다. 문서에 "이 기능을 쓰면 오피스 관리의 구성원·조직관리 기능을 이용할 수 없다"고 명시되어 있다. 쓰면 인사팀이 하이웍스에서 직원을 관리하지 못하게 된다 |
| OAuth 인증, 내 정보 조회 | 문서에 deprecated로 표시. 신규 발급을 지원하지 않는다 |
| SSO 내부로 연동 | 포털 안에 하이웍스 화면을 넣는 기능이다. 이번 목적(포털 로그인)과 반대 방향이다 |
| 문자·알림톡 | 건당 과금 구조로 보인다 (잔여 건수 조회 API가 따로 있음) |

## 5. 기능별 동작 흐름

### 로그인 (SSO, "외부로 연동")
1. 직원이 하이웍스 화면에서 "인사포털" 인트라넷 메뉴를 누른다.
2. 하이웍스가 `등록한 연동 URL?token={token}`으로 보낸다.
3. 서버가 link-api로 token을 조회해 user-no·아이디·이름·사번을 받는다.
4. 서버가 포털 세션을 발급한다.

출입구는 **하이웍스 메뉴**다. 포털 주소로 바로 들어온 사람은 하이웍스로 안내해야 한다 (#42 댓글 ⑤ 참고). 포털 화면에서 시작하는 로그인(OAuth)은 지원이 중단되었다.

### 조직도
서버가 하루 1회 조직도·사용자 조회 API를 호출해 저장해 두고, 화면은 저장본을 쓴다.

### 전자결재 (KPI 승인 등)
1. 포털에서 [결재 올리기]를 누른다.
2. 서버가 기안 API를 호출해 `login_url`을 받는다.
3. 브라우저가 `login_url`을 팝업으로 연다. 하이웍스 로그인 후 내용이 채워진 기안 문서가 열린다.
4. **직원이 결재선을 지정하고 [기안하기]를 누른다** (완전 자동 상신이 아니다).
5. 상태가 바뀔 때마다 하이웍스가 `callback_url`로 GET 요청을 보낸다.
   `office_id, approval_key, approval_id, approval_code, state, request_hash`
   state 값: `progress`(기안) / `rejected`(반려) / `canceled`(기안 취소) / `complete`(결재 완료) / `deleted`(삭제)

### 알림
서버가 알림 발송 API에 받는 사람 아이디 목록, 메시지, 누르면 이동할 링크를 담아 호출한다.

## 6. 리스크와 대응

| 리스크 | 근거 | 대응 |
|---|---|---|
| **결재 콜백 위조 가능** | `request_hash`는 서명이 아니라 기안할 때 넣은 `state` 값을 그대로 돌려주는 값이다 | 콜백을 받으면 **문서 상태 조회 API로 실제 상태를 다시 확인**한 뒤 반영한다. `state`에는 추측하기 어려운 무작위 값을 넣어 요청과 대조한다 |
| 오피스 토큰 권한이 크다 | 매뉴얼: "그룹웨어 전체를 관리하는 API 인증키" | Scope는 최소 3개만 켜고 IP 제한을 적용한다. `.env`에만 보관한다 |
| 토큰 재발급 시 연동 중단 | 매뉴얼 명시 | 재발급과 `.env` 교체를 같은 날 함께 한다 |
| 호출 한도 하루 1,000건 | 오피스(회사) 단위, 성공한 호출 기준 | 조직도는 하루 1회만 가져온다. 알림은 user_list로 묶어 보낸다 |
| SSO 토큰 유효시간·1회용 여부 | **문서에 없음** | 실제 연결 테스트로 확인한다 |
| 직급·직위 정보 | 조직도·사용자 조회 응답 예시에 **없음** | 가비아 문의 결과에 따라 포털에서 직급을 따로 입력받는다 |
| 근태 조회 | **문서에 없음**. 토큰 Scope의 "인사(캡스 연동)"가 출입 기록일 가능성이 있으나 미확인 | 가비아에 문의한다 |
| 요금제 조건 | **문서에 없음** | 가비아에 문의한다 (#42 본문 ①) |
