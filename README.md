# hr-portal — 인사 통합포털

주식회사 에이치앤아비즈(HnAbiz) 사내 인사 통합포털.
임직원의 근태·급여·출장·평가·규정 조회를 단일 포털로 통합하는 것을 목표로 한다.

> ### 📘 [초심자 가이드 — 처음이라면 여기부터](docs/beginner-guide.md)
> 개발 경험이 전혀 없어도 따라 할 수 있는 문서다. **브라우저 하나만 있으면 된다** — 서버 접속도, 프로그램 설치도 필요 없다.
> GitHub에서 화면을 고치고, 확인 요청(PR)을 올리고, 미리보기로 결과를 확인하는 절차를 처음부터 설명한다.
>
> ### 🔧 [관리자 가이드 — 서버를 직접 다루는 담당자용](docs/admin-guide.md)
> SSH 접속, 컨테이너·터널 운영, 장애 점검 절차. Tailscale 접근 권한이 있는 담당자만 해당된다.

> **현재 단계: PoC (Proof of Concept)**
> 화면 구조(IA) 검증과 외부 접근 경로 검증만 완료된 상태이며, 백엔드·인증·실데이터는 구현되지 않았다.
> 표시되는 모든 데이터는 하드코딩된 가상 데이터다.

## 2. 시스템 구성

```
인터넷
  │
  ▼
Cloudflare Edge (icn01 / icn05 / icn06)
  │  TLS 종단, (예정) Access 인증
  ▼
Cloudflare Tunnel  "hr-portal-dev"
  │  tunnel id: 1570ba07-e6dd-4535-9929-9ab7b7daa82d
  │  아웃바운드 QUIC 연결만 사용 — 인바운드 포트 개방 없음
  ▼
127.0.0.1:8080
  │
  ▼
Docker 컨테이너  "hr-portal-web"  (nginx:alpine)
  │  bind mount (읽기 전용)
  ▼
./public/
```

### 호스트 환경

| 항목 | 값 |
|---|---|
| 서버 | `abyz-lab0-OptiPlex-3060` |
| OS | Ubuntu 24.04.4 LTS |
| 접속 주소 | https://hr.abyz-lab.work |
| 로컬 바인딩 | `127.0.0.1:8080` (외부·사내망 직접 노출 없음) |
| cloudflared | systemd 서비스, 부팅 시 자동 시작 |
| 설정 파일 | `/etc/cloudflared/config.yml` |

### 설계 원칙

- **호스트 nginx를 경유하지 않는다.** Cloudflare Tunnel의 ingress 규칙이 호스트명 라우팅을 담당하고 TLS는 Cloudflare가 종단하므로, 호스트 nginx는 중복 계층이다. 같은 서버의 기존 서비스(`voc-mr-ecr`)와 완전히 분리된다.
- **서빙 대상은 `public/`만 마운트한다.** 저장소 루트를 마운트하면 `.git`이 웹으로 노출된다.
- **로컬 바인딩은 `127.0.0.1`로 한정한다.** cloudflared만 접근하면 되므로 사내망에도 열지 않는다.
- **서비스 1개 = compose 스택 1개 + 로컬 포트 1개 + ingress 규칙 1줄.** 서비스 증설 시 이 패턴을 따른다.

## 4. 운영

### 코드 반영

바인드 마운트 방식이라 `git pull`만으로 즉시 반영된다. 컨테이너 재시작이 필요 없다.

```bash
cd ~/workspace/github-hnabyz-bot/hr-portal && git pull
```

### 컨테이너

```bash
docker compose up -d      # 기동
docker compose down       # 중지
docker compose logs -f    # 로그
docker ps --filter name=hr-portal
```

### 터널

```bash
sudo systemctl status cloudflared
sudo systemctl restart cloudflared
sudo journalctl -u cloudflared -f
```

### 점검

```bash
curl -I http://127.0.0.1:8080/          # 컨테이너 직접
curl -I https://hr.abyz-lab.work        # 외부 경로 전체
```

## 5. 로드맵

의존 관계 순으로 정렬했다. 상위 단계를 건너뛰면 하위 단계에서 재작업이 발생한다.

### Phase 0 — PoC 기반 구축 (완료)

- [x] 화면 구조(IA) 초안 작성 — 9개 대메뉴 / 25개 서브탭
- [x] GitHub Private 저장소 연동 (Deploy key 방식)
- [x] Docker 기반 정적 서빙 구성
- [x] Cloudflare Tunnel 생성 및 systemd 등록
- [x] DNS 레코드 등록 (`hr.abyz-lab.work`)
- [x] 외부 접근 경로 검증

### Phase 1 — 기반 정비

실데이터를 다루기 전에 반드시 끝내야 하는 항목들이다.

- [ ] Cloudflare Access 정책 적용 (Self-hosted, Action=Allow, Include=Emails)
- [ ] IdP 연동 — Google Workspace 또는 Entra ID SSO + MFA
- [ ] 미사용 DNS 레코드 정리 (`hr-dev` CNAME 삭제)
- [ ] 터널 이름 정리 (`hr-portal-dev` → `hr-portal`, 대시보드에서 변경)
- [ ] 환경 분리 설계 — dev / staging / prod 호스트명 및 배포 경로 확정
- [ ] 백업 정책 수립 (DB 도입 전 미리 설계)

### Phase 1.5 — 협업 환경 구축

서버 접근 권한(Tailscale) 없이도 작업할 수 있게 만드는 단계.
**비개발자 작업자를 합류시키기 전에 반드시 완료해야 한다.** 초심자 가이드가 이 구성을 전제로 작성되어 있다.

- [ ] `release` 브랜치 생성 — 검증 통과분만 도달하는 배포 기준 브랜치
- [ ] 서버 자동 배포 구성 — systemd 타이머로 `release` 주기 확인 (Pull 방식)
      *서버가 Tailscale 뒤에 있어 GitHub이 서버로 들어올 수 없다. 서버가 나가서 가져오는 방식만 가능하다*
- [ ] `main` 직접 push 차단 + PR 필수화 (플랜별 지원 여부 확인 필요)
- [ ] 자동 검사(CI) 구성 — GitHub 호스팅 러너에서 실행
  - [ ] HTML 문법 검사
  - [ ] 시크릿 스캔 (비밀번호·토큰 커밋 차단)
  - [ ] 개인정보 패턴 검사 (주민번호·연락처 형식)
  - [ ] `public/` 노출 대상 검사
  - [ ] 스모크 테스트 (컨테이너 기동 후 200 응답 확인)
  - [ ] 한글 인코딩 검사
- [ ] PR별 미리보기 환경 구성 (Cloudflare Pages)
- [ ] PR 템플릿 작성 (변경 내용 체크리스트)
- [ ] 작업자 GitHub 권한 부여 (Write, main push 불가)

> **CI는 GitHub 호스팅 러너에서 실행한다.** 우리 서버에 접근할 수 없는 환경이므로,
> PR에 어떤 코드가 들어와도 서버는 안전하다. 빌드가 필요해지는 Phase 4 시점에
> self-hosted runner 전환을 검토한다.

### Phase 2 — 요구사항 확정

화면부터 만들면 반드시 뒤집힌다. 이 단계를 먼저 닫는다.

- [ ] **역할(권한) 모델 정의** — 임직원 / 팀장 / 인사담당 / 시스템관리자
- [ ] 역할별 메뉴·기능 노출 규칙 매트릭스 작성
- [ ] 관리자 기능 분리 — 현재 `마이페이지 > 접근권한`에 섞여 있음
- [ ] 결재선 정책 정의 (단계, 전결 규정, 부재 시 대결·위임)
- [ ] 근태 규칙 확정 — 유연근무제, 재택·외근, 주 52시간 한도, 대체휴무·보상휴가
- [ ] 휴가 종류 체계 확정 — 연차/반차/반반차/병가/경조사/공가/육아휴직
- [ ] 연차 산정 방식 확정 (회계연도 기준 여부, 촉진제도 운영)
- [ ] 출장비 규정 반영 — 직급별 한도, 지역 구분, 초과 시 처리
- [ ] 평가 프로세스 확정 — 자기평가, 1·2차 평가, 이의제기 절차
- [ ] 기존 인사 시스템·엑셀 대장 현황 조사 및 데이터 이관 범위 확정

### Phase 3 — 누락 모듈 설계

문서 리뷰에서 확인된 미반영 영역이다. IA에 먼저 추가하고 Phase 2와 함께 확정한다.

- [ ] **전자결재** — 결재함, 결재 이력, 결재선 설정, 위임 (현재 홈 위젯만 존재)
- [ ] **교육·훈련 관리** — 계획/실시/이수/유효성 평가 기록
      *ISO 13485 6.2 및 KGMP 요구사항. 별도 엑셀 운영 시 심사 대응에 불리하다.*
- [ ] **인사기록카드** — 학력·경력·자격증·발령이력
- [ ] **증명서 발급** — 재직/경력/원천징수 온라인 즉시 발급 (현재 신청서 다운로드만)
- [ ] 입·퇴사 관리 — 온보딩/오프보딩 체크리스트
- [ ] 복리후생·경조사 신청
- [ ] 건강검진 관리
- [ ] 인사발령 공고
- [ ] 팀 캘린더 (현재 휴가 캘린더에서 참조하나 화면 없음)

### Phase 4 — 기술 기반 구축

- [ ] 기술 스택 선정 (프론트엔드 / 백엔드 / DB)
- [ ] DB 스키마 설계 — 인사 마스터, 근태, 급여, 결재, 감사로그
- [ ] 인증·세션 구현 (SSO 연계)
- [ ] **서버측 권한 검증 구현** — 프론트에서 메뉴를 숨기는 것만으로는 API 직접 호출을 막지 못한다
- [ ] 감사로그 설계 — 누가/언제/누구의 어떤 정보를 조회했는지
- [ ] API 설계 및 문서화
- [ ] CI/CD 구성 — self-hosted runner (서버가 Tailscale 뒤에 있어 Webhook 인바운드 불가)
- [ ] 스테이징 환경 구성

### Phase 5 — 프론트엔드 재구축

현재 프로토타입은 구조 검증용이며 그대로 확장할 수 없다.

- [ ] 프레임워크 이전 — 현재 `innerHTML` + 전역 함수 구조
- [ ] **라우팅 도입** — 현재 URL이 바뀌지 않아 새로고침·뒤로가기·링크 공유 불가
- [ ] **상태 유실 해결** — 탭 전환 시 DOM 전체 재생성으로 입력값 소실
- [ ] **XSS 방어** — `innerHTML` + 템플릿 리터럴에 API 응답 연결 시 저장형 XSS 경로가 된다
- [ ] **반응형 지원** — 현재 `height:100vh; overflow:hidden` + 사이드바 240px 고정으로 모바일 사용 불가
      *출퇴근 체크·연차 신청은 모바일 사용 비중이 가장 높다*
- [ ] **웹접근성 대응** — 내비게이션이 `<div onclick>`, 버튼이 `<span>`이라 키보드·스크린리더 미동작
- [ ] `<label>` / `<input>` 연결 (`for` / `id`)
- [ ] 디자인 시스템 정리 — 현재 CSS 변수 기반 토큰은 재사용 가능

### Phase 6 — 컴플라이언스

급여·평가·주민번호를 다루므로 「개인정보의 안전성 확보조치 기준」 적용 대상이다.

- [ ] 개인정보 처리 항목·목적·보유기간 정의
- [ ] 외부 접속 시 안전한 인증수단 적용 (2단계 인증 등)
- [ ] 접속기록 보관 — 최소 1년, 고유식별정보·민감정보 처리 시 2년
- [ ] 민감 화면(급여·평가) 재인증 및 마스킹 정책
- [ ] 다운로드 이력 로깅
- [ ] 개인정보 국외이전 검토 — Cloudflare 엣지 경유에 대한 사내 규정 정합성
      *필요 시 Cloudflare Regional Services로 국내 처리 고정 가능(유료)*
- [ ] 망분리 의무 해당 여부 확인
- [ ] 개인정보처리방침 반영
- [ ] 취약점 점검

### Phase 7 — 운영 전환

- [ ] 실데이터 이관 및 검증
- [ ] 사용자 교육 및 매뉴얼 배포

| 초과근무 | 사전신청만 있고 실적 등록·승인 단계 없음 (수당 지급 근거는 실적) |
| 평가 | 자기평가 작성 화면 없음, 이의제기 메뉴 없음(FAQ에만 언급) |
| 경비 산출기 | 규정 한도 검증 미구현(안내 문구만), 음수·비정상 입력 방어 없음 |
| 검색 | 상단 통합검색과 규정 검색의 역할 경계 불명확 |
| 조직도 | 드릴다운 없음, 팀 캘린더 링크 대상 화면 부재 |
| 알림 설정 | ON 배지가 토글로 동작하지 않음 |
